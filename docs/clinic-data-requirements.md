# Формат карт для MedCheck

## 1. Запрос пакета

API клиники принимает query-параметр `date`:

```http
GET <CLINIC_API_URL>?date=2026-08-03
Accept: application/json
```

`date` имеет формат `YYYY-MM-DD`. Он указывает дату карт, которые нужно
вернуть. Используйте его для повторной загрузки карт за прошедшую дату после
сбоя.

## 2. Пакет карт

При пакетной передаче API клиники может вернуть один из двух JSON-форматов.

Формат 1 — объект с ключом `appointments`:

```json
{
  "appointments": [
    {
      "Прием": {
        "GUID": "8d96a4da-018a-4d55-a66c-5962643a23dc",
        "NUM": "123456",
        "DATE": "2026-08-03",
        "Врач_код": "00012",
        "Врач": "Иванова Анна Сергеевна"
      },
      "Врач": {
        "SPECIALIZATION": "Педиатр"
      },
      "Пациент": {
        "CODE": "P-000001",
        "GENDER": "Женский",
        "AGE": 12
      },
      "Услуги": [
        {
          "КодЕГИСЗ": "B04.031.002",
          "Наименование": "Осмотр врача-педиатра"
        }
      ],
      "ДанныеОсмотра": [
        {
          "Параметр": "Жалобы",
          "Значение": "Боль в горле два дня"
        }
      ],
      "Диагнозы": [
        {
          "КодМКБ": "J06.9",
          "НаименованиеМКБ": "Острая инфекция верхних дыхательных путей",
          "Детализация": "",
          "ВыявленВпервые": true
        }
      ]
    }
  ]
}
```

Формат 2 — корневой массив карт:

```json
[
  {"Прием": {"GUID": "..."}, "...": "..."}
]
```

Каждая карта в корневом массиве должна содержать все поля из раздела 2.

`appointments` и корневой массив содержат карты. Один элемент массива — одна
карта одного приёма. Не передавайте одну карту отдельным JSON-объектом вне
массива. Не оборачивайте объект `appointments` в дополнительный массив.

Если приёмов нет, API возвращает один из двух вариантов:

```json
{"appointments": []}
```

```json
[]
```

Используйте `Content-Type: application/json; charset=utf-8`.

## 3. Поля карты

| Поле | Тип | Требование |
|---|---|---|
| `Прием.GUID` | строка | Уникальный неизменяемый идентификатор приёма. |
| `Прием.NUM` | строка | Номер приёма в МИС или 1С. |
| `Прием.DATE` | строка | Дата приёма строго в формате `YYYY-MM-DD`. |
| `Прием.Врач_код` | строка | Постоянный код врача в МИС или 1С. |
| `Прием.Врач` | строка | ФИО врача. Обязательно при наличии `Врач_код`. |
| `Врач.SPECIALIZATION` | строка | Специализация врача. |
| `Пациент.CODE` | строка | Внутренний код пациента. |
| `Пациент.GENDER` | строка | Только `Мужской` или `Женский`. |
| `Пациент.AGE` | число | Возраст пациента целым числом. |
| `Услуги` | массив | Массив услуг. Каждый элемент содержит `КодЕГИСЗ` и `Наименование`. |
| `ДанныеОсмотра` | массив | Массив элементов `Параметр` и `Значение`. Оба поля непустые строки. |
| `Диагнозы` | массив | Массив диагнозов. Каждый элемент содержит `КодМКБ`, `НаименованиеМКБ`, `Детализация` и `ВыявленВпервые`. |

Все ключи из таблицы обязательны. Если услуг или диагнозов нет, передавайте
пустой массив `[]`. Не передавайте `null` вместо массива. `ВыявленВпервые`
имеет тип Boolean: только `true` или `false`.

Не передавайте ФИО пациента, телефон, адрес, паспортные данные, СНИЛС и
другие прямые идентификаторы пациента.

## 4. Правила идентификации и обновления

1. Используйте один `Прием.GUID` для одного приёма.
2. При исправлении карты сохраняйте её `Прием.GUID`.
3. Не используйте один `Прием.GUID` для двух разных приёмов.
4. Не меняйте `Прием.Врач_код` при исправлении ФИО врача.
5. Не используйте один `Прием.Врач_код` для двух разных врачей.

## 5. Тестирование

Перед запуском передайте ответ API с не менее чем 10 картами в массиве
`appointments`. MedCheck проверяет JSON, обязательные поля и обработку карт.

Обзор системы

medkard — система автоматического аудита амбулаторных карт (записей о визитах пациентов к врачу). Забирает записи из МИС на базе 1С, проверяет их LLM-моделью по трём измерениям качества и отдаёт результаты Excel-отчётами и HTTP-API. Визиты приходят из 1С обезличенными; LLM и эмбеддинги работают через self-hosted OpenAI-совместимый эндпоинт (vLLM); база — Postgres с pgvector.

ИЗМЕРЕНИЕ 1
Формальная структура

Присутствуют ли обязательные разделы записи (жалобы, анамнез, осмотр…) для типа визита и возраста. Правила из приказов МЗ 274н/203н в rules.json.

ИЗМЕРЕНИЕ 2
Кодирование МКБ-10

Соответствует ли выставленный код диагноза содержимому записи. Агент может предложить исправленный код → повторный аудит.

ИЗМЕРЕНИЕ 3
Клинические рекомендации

Соответствует ли запись (анамнез, обследование, лечение) клинрекам Минздрава для диагноза. Тексты клинреков (PDF) проиндексированы в RAG.

Дедупликация

done_cards.card_guid UNIQUE; перед прогоном грузятся все GUID организации, включая ignored и broken — они не переаудируются.

Два DB-стека

psycopg3 — весь CRUD (storage/); asyncpg — только векторный поиск (RAG/retrieval/vector_store.py). Отдельные пулы к одной базе.

Excel пишет НЕ пайплайн

Экспорт вынесен в ExcelFormatter, который читает готовые результаты из done_cards. Пайплайн только пишет в БД.

Возрастные пороги расходятся

Formal считает ребёнком age < 18, подбор клинреков/ICD — age ≤ 15. Осознанно не выровнено.

ChineseDetector

Некоторые модели галлюцинируют CJK-иероглифы в русском тексте; каждый issue проверяется регексом, «заражённые» чинятся отдельным LLM-вызовом.

Мультиарендность

Организации Alenka/MDS; каждая done_cards-строка привязана к organization_id; все отчёты и API жёстко scoped по нему.

Пайплайн аудита одного прогона

AuditPipeline.run_batched() оркестрирует аудит партии визитов: дедупликация, фильтрация, три измерения, запись в done_cards. Конкурентность — asyncio.Semaphore(num_batches) на визиты (внутри визита ещё до 3 параллельных diagnosis-агентов). Любое исключение в _audit_visit → upsert_broken, визит выпадает, батч продолжается. Excel пайплайн не пишет.

Ветвления судьбы визита

GUID уже в done_guids

skip (skipped_done), не аудируется. Карты без GUID аудируются всегда (дедуп невозможен, warning).

Срезан стратегией

Icd/KDL/Analysis → upsert_ignored (ignored=TRUE), не аудируется.

Нет диагнозов

Только formal, ранний возврат — измерения 2 и 3 не запускаются.

Гайдлайн не найден

guideline_file_id=None, чекеры не запускаются: «Клинические рекомендации для данного кода не найдены».

Диагноз в IcdFilter

Заглушка-issue «Диагноз пропущен фильтром МКБ» вместо клин-рек аудита.

Исключение

upsert_broken, выпадает из результата. broken → в get_done_guids — не переаудируется без ручного вмешательства.

RAG: ингест клинреков и ретривал

Тексты клинических рекомендаций (PDF) индексируются офлайн в таблицу docs, а в рантайме тулзы агентов ищут по ним гибридным поиском. Reverse HyDE удалён — никаких гипотетических вопросов и трёх колонок эмбеддингов; на чанк один эмбеддинг contextual text "[секция]\nтело", колонка embedding VECTOR(1024) с HNSW-индексом.

Ингест (офлайн · scripts/reingest-pdfs.py)

PDF → PyMuPDF (TOC/таблицы) → нарезка на секции и чанки → эмбеддинг contextual text → docs + guidelines + ingest_runs.

Ключевой нюанс: эмбеддится текст с префиксом секции, а в docs.chunk пишется тело без префикса. Одноуровневые заголовки (3 Лечение) регуляркой ингеста не ловятся — их добирает subtree-фильтр ретривала.

Ретривал (рантайм · тулзы агентов)

Запрос агента → embed → векторный HNSW-этап (file_id + секционный subtree-фильтр, кандидатов top_k×6) → BM25 по кандидатам → RRF k=50 → топ-4.

Секционный subtree-фильтр и scoped-поиск

Subtree-фильтр

Старый плоский LIKE '%kw%' расширен на номерное поддерево: 3 Лечение → паттерны ['3 %','3.%']. Запрос про лечение достаёт и подсекции без слова «лечен» (3.4 Обезболивание).

Scoped-функции

search_anamnesis → keyword жалоб; search_inspection → исследов; search_treatment → лечен. TARGETED_TOP_K=4, кандидатов 24.

BM25 в Python

Полнотекстового tsvector-индекса по docs нет. BM25Okapi по кандидатам векторного этапа → lexical recall ограничен выдачей HNSW.

Эмбеддинги

Провайдеры: openai (деф.), st (sentence-transformers), fastembed (ONNX Qwen3-0.6B). EMBEDDING_DIM деф. 1024, зашит литералом в SQL.

Исключение литературы

Чанки с «Список литературы» исключаются WHERE-фильтром на векторном этапе; порогов по distance/rrf_score нет — просто топ-N.

Reingest planner

Классификация work-list: full (нет записи / sha256 PDF изменился) · metadata_only · skip. full-реингест = атомарный replace_by_file_id.

LLM-слой: карта вызовов на визит

Все LLM-вызовы проекта идут через единый LLMClient (src/LLM/client.py) — ретраи (до 3 попыток, температура +0.15 за попытку, cap 1.0), structured output (response_format=json_schema) и агентный враппер. Прямых вызовов AsyncOpenAI в аудиторском коде нет. Итог на визит: 2 + 3N + 3k вызовов (N — диагнозов, k — с предложенным кодом), плюс decider/picker и chinese-repair. VisitClassifier не вызывается — тип визита определяет regex-эвристика.

База данных: схема и связи

Postgres + pgvector. Два стека к одной базе: psycopg3 (весь CRUD, storage/) и asyncpg (только векторный поиск по docs). Миграции 001–024 через migrate.sh с леджером schema_migrations. Два файла 013 применяются оба в алфавитном порядке.

Storage-классы (src/storage/, psycopg3, паттерн BaseStorage)

DoneCardsStorage

Все пути — upsert по card_guid: upsert (форсит ignored=FALSE, снимает broken), upsert_ignored, upsert_broken, get_done_guids (включая ignored/broken, NULL-safe).

DocsStorage

Свой пул (max 3) + pgvector. replace_by_file_id атомарно, get с LEFT JOIN guidelines (денормализует name/mkb/age_category в Doc).

GuidelinesStorage

find_by_code (= ANY(mkb)), find_by_prefix (unnest+split_part), all, upsert_many.

ApiKeysStorage

create_key, revoke_key, is_key_authorized_for_org, is_valid_key. Сырой ключ не хранится — только SHA-256.

drugs / dietary_supplements

Изолированные справочники для search_medicine: триграммы (drugs) + full-text tsvector (supplements). Наполнение seed-reference-lists.sh.

Модели — датаклассы

Не ORM. result.py: Result, FormalStructureResult, DiagnosisResult, IcdCodingIssue — сериализуются в JSONB-колонки done_cards.

API и интеграции

Два контура выдачи, оба читают одну таблицу done_cards и общий парсер reporting/result_parser.py. Push: 1С → аудит → done_cards → Excel на диске → FTP. Pull: внешнее интегрирующее приложение по HTTP тянет из done_cards (Bearer-ключ + ?org=), трафик — приватный WireGuard-туннель. Браузерного контура нет (нет CORS).

Эндпоинты (src/api/routes/cards.py, префикс /cards)

GET /cards/check

date (ISO), org → {date, count} — число аудированных (не ignored/broken) карт за дату визита. 401/403/404 auth, 422.

GET /cards/pull

date, org → xlsx-байты (тот же layout, что дисковые отчёты). 404 если карт нет; 401/403/422.

GET /cards/export

since, limit (0=∞), cursor (OFFSET), org → сырые строки для реплики engine. Сортировка по updated_at, card_guid; контракт закреплён тестом (token_count/org_id исключены).

Аутентификация

Ключ medkard_<token_urlsafe(32)>, в БД только SHA-256 + prefix. Резолв org case-insensitive → 404; scope не совпал → 403; невалиден/отозван → 401.

Деплой Docker

python:3.11-slim + uv + requirements-api.txt (без LLM/RAG). CMD uvicorn api.app:create_app --factory. В образе только pull-API — аудит/ингест/миграции вне контейнера.

WireGuard

Порт ${WG_BIND_IP}:8000:8000 — только на WG-интерфейсе. Postgres внешний. POSTGRES_HOST=localhost из контейнера не достучится до хостового Postgres.

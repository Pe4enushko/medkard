Технические требования к интеграции МИС/1С с MedCheck и «Искрой»

Технический контракт для пакетного получения приёмов и передачи сведений о проведённых приёмах.

1. Потоки данных и назначение

Интеграция включает два обязательных потока данных. Передача MedCheck в «Искру» является внутренней частью интеграции и показана только для понимания пути данных.

МИС или 1С отправляет каждый проведённый приём в MedCheck отдельным push-запросом.

Значения в угловых скобках в примерах являются шаблонами. При настройке используются предоставленные значения.

Жизненный цикл ключа доступа MedCheck

  1. MedCheck создаёт ключ доступа и передаёт его клинике.
  2. МИС или 1С использует действующий ключ в заголовке Authorization каждого push-запроса.
  3. При подозрении на компрометацию ключа клиника прекращает его использование. MedCheck отключает прежний ключ и передаёт новый.

5. Идентификация и обновление приёмов

  1. Для каждого приёма используется отдельное значение Прием.GUID.
  2. При исправлении приёма значение Прием.GUID сохраняется.
  3. Значение Прием.Врач_код постоянно для одного врача.

6. Push проведённого приёма

Операция POST /visits/push выполняется после успешного проведения документа приёма в 1С. К моменту выполнения операции должны быть сформированы GUID, номер, дата и данные осмотра. При повторном проведении изменённого приёма операция выполняется повторно.

HTTP
POST <адрес API MedCheck>/visits/push?org=<код организации>
Authorization: Bearer <ключ доступа>
Content-Type: application/json; charset=utf-8

Адрес API MedCheck, код организации и ключ доступа предоставляются MedCheck. Тело запроса содержит один объект приёма из массива раздела 3.

7. Подтверждение доставки и обработка ошибок

HTTP 200

MedCheck принял приём для обработки.

JSON
{
  "card_guid": "8d96a4da-018a-4d55-a66c-5962643a23dc",
  "status": "pending"
}
status: pending

card_guid соответствует Прием.GUID переданного приёма. Значение pending означает, что приём принят для обработки.

Приём считается доставленным в MedCheck при выполнении двух условий: получен ответ 200, а card_guid в ответе совпадает с Прием.GUID запроса. В этом случае задача отправки завершается. Значение pending не является статусом завершения обработки в «Искре».

Если ответ не получен, имеет код, отличный от 200, либо содержит другой card_guid, задача отправки остаётся в очереди. МИС или 1С повторяет запрос с тем же Прием.GUID и ограниченной экспоненциальной задержкой. Повторный запрос обновляет ранее принятый приём с тем же GUID.

ОтветДействие
200Задача отправки завершается.
401 или 403Проверяются ключ доступа и код организации.
422Исправляется формат приёма; выполняется повторная отправка.
5xx или ошибка сетиПланируется повторная отправка с ограниченной экспоненциальной задержкой.

8. Обезличивание, хранение и удаление приёмов

МИС или 1С выполняет обезличивание до передачи приёма в MedCheck. MedCheck и «Искра» хранят переданные данные без изменения.

Исправленный приём передаётся повторно с прежним Прием.GUID. Удаление или отмена приёма в МИС или 1С не передаётся в MedCheck: API удаления приёма пока не предоставляется.

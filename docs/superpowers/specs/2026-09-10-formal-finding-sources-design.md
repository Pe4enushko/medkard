# Слепок правила в формальном замечании

**Зачем.** Движок «Искры» строит по замечаниям аудита персональные задачи врачам, а
теперь ещё и пятничное тестирование с проверкой ответов
(`engine/docs/superpowers/specs/2026-09-07-doctor-quiz-design.md`). Проверяющему нужен
**эталон** — текст требования, по которому замечание выставлено.

У диагностических замечаний он уже есть: `diag_result` несёт `sources[].cite` —
дословную цитату клинрека, плюс `chunk_id` и снимок редакции. У формальных не было
ничего, кроме короткого ярлыка приказа (`274n`).

## Что сделано в этой ветке

`formal_result` теперь несёт **слепок правила**, снятый в момент проверки:

```json
{"flag": "ОТСУТСТВУЮТ_МЕТАДАННЫЕ_ВИЗИТА",
 "issue": "...", "comment": "",
 "rule_id": "visit_meta_required",
 "source": "274n",
 "severity": "критичный",
 "source_ref": "приказ МЗ РФ от 13.05.2025 № 274н, прил. 1 (форма 025/у), стр. 1–2 …",
 "expectation": "В записи должны быть идентифицируемы дата приёма, возраст, пол …",
 "verified_at": "2026-08-19"}
```

Состав слепка — `SNAPSHOT_FIELDS` в `storage/models/result.py`, единственное объявление.
Все шесть полей берутся из `rules.json` **один в один, без разбора строк**.

Снимается слепок в `FormalValidator.validate`, где правило уже в руках рядом со своими
замечаниями (`zip(rules, atomic_results)`). Поиск по флагу не используется намеренно:
у `ДИСПАНСЕРНОЕ_НАБЛЮДЕНИЕ_НЕ_ОТРАЖЕНО` два правила — взрослое 168н и детское 192н, и
словарь `flag → source` одно из них молча затирает.

Синтетические замечания (незаполненные поля шаблона, противоречие НМУ) правила не имеют
и получают **пустой** слепок, а не выдуманный.

### Почему слепок, а не ссылка на каталог

Каталог версионируется: `rules.json` несёт `revised_at`, каждое правило — свой
`verified_at`, а источник может смениться по календарю. Живой пример:
`xray_protocol_and_conclusion` до сих пор указывает на 560н, который утратил силу
**01.09.2026** — в реестре источников на эту дату стоит запись «сменить `source` на
`359n`». Ссылка на каталог означала бы, что старые замечания задним числом начнут
судиться новым текстом. Тот же довод, по которому у клинреков `guideline_meta` записан
снимком редакции, а не ссылкой на манифест.

## Что НЕ сделано и почему

### Дословная цитата (`cite`)

Один в один не берётся. Цитаты лежат в `docs/superpowers/research/2026-08-18-npa-pdf/`
(11 файлов, ~100 КБ) строками формата `[стр. N PDF] п. X: «цитата» — зачем (rule_id)`.

Связь **многие-ко-многим**: один буллет в `274n.md` перечисляет девять правил сразу,
часть — через звёздочку (`treatment_*`, `sick_leave_*`, `consent_*`, `dispensary_*`).
Одна цитата обслуживает много правил, одно правило собирает цитаты с разных страниц.

Покрытие правил выжимками (замер 10.09.2026, 42 правила):

| | сколько | что делать |
|---|---|---|
| названы точно по `rule_id` | 35 | цитата достаётся |
| только через `prophylactic_*` | 3 | раскрыть метку руками |
| источник `icd10` | 2 | цитаты приказа быть не может: МКБ-10 — справочник, не НПА |
| `has_typos` | 1 | источника нет по решению реестра — внутренний стандарт качества |
| `legal_representative_info` | 1 | **пробел**: ни точной метки, ни подстановочной |

Отсюда `cite` обязан быть **nullable**: три правила бессточны по природе предмета, и
заполнять их поле было бы враньём.

**Как делать:** не парсером по прозе, а **явным вычитанным файлом соответствия**
`rule_id → {doc_title, section, cite}`, закоммиченным и отревьюенным глазами. Разметка
человеческая, со звёздочками и перечнями; парсер по ней будет ошибаться молча.

Три оговорки к самим выжимкам: это **первоначальные редакции без поправок** (сканы
pravo.gov.ru), покрытие **по выбранным пунктам**, а не по документу (на неполноте уже
обжигались 28.08 — вывод «приказами не предусмотрено» оказался неверным), и цитаты
**сняты глазами**, без текстового слоя для сверки.

### Разложение `source_ref` на документ и раздел

`source_ref` — составная строка: документ плюс несколько разделов в одном поле. Разбор
её на `doc_title`/`section` не является отображением один-в-один. Хранится целиком:
она написана для человека и в таком виде полезнее разрезанной.

### Бэкфилл

Исторические строки `done_cards` слепка не имеют. Пустые поля читаются как «слепка нет»,
а не «правило без источника» — так и написано в `parse_formal`.

Бэкфилл делать **одним прогоном вместе с цитатой**, а не отдельно: иначе история
получит промежуточный слепок без `cite`, и прогон придётся повторять. Для правил, где
флаг делится между взрослой и детской парой, правило восстанавливается по возрасту
пациента из карты.

## Замеченное рядом, не тронуто

`_enrich_flags` и `_FLAG_SOURCE` в валидаторе — **мёртвый код**: вызывающих ноль.
Защита от неизвестного флага там не нужна с переходом на атомарную проверку, потому что
флаг проставляет код (`validate_rule`), а не модель. Удалять отдельной задачей.

`xray_protocol_and_conclusion` указывает на утративший силу 560н — переключение на 359н
просрочено с 01.09.2026. Текст замены уже вычитан в `464n-359n.md`, не сделан только
сам переключатель.

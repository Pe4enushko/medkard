# fix-broken — переаудит упавших карт

**Дата:** 2026-08-07
**Ветка:** `fix-broken` (от `origin/release` @ `c89e5a8`)
**Worktree:** `/home/savoy/projects/medkard-fix-broken`

## Задача

Карты, упавшие с исключением во время аудита, заморожены навсегда. Нужен
скрипт, который переаудирует их — по одной организации или по всем сразу.

## Почему они заморожены

Упавшая карта — строка `done_cards` с `broken = TRUE`, `status = 'done'`,
сохранённым `card_data`, стектрейсом и NULL во всех колонках результатов
(`upsert_broken`, `src/storage/done_cards_storage.py:199`).

`broken` — булева колонка, а не значение `status`. `status` принимает только
`pending` и `done`; у упавшей карты он `done`, потому что падение — это
терминальный исход прогона.

Заморозка складывается из двух шагов:

1. `AuditPipeline.run_batched` грузит `get_done_guids()`
   (`src/audit/pipeline.py:97`), а тот отдаёт все GUID со `status = 'done'` —
   **включая broken** (`docs/storage.md:69`).
2. `CardFilter.filter` отсеивает всё, что попало в `done_guids`
   (`src/audit/filters.py:159-165`).

Ночной периодный прогон такую карту не подберёт никогда, сколько бы раз она
ни попала в выборку из 1С.

## Решение

Читаем broken-строки из БД и отдаём их `card_data` в пайплайн с
**`done_guids=set()`** — пустой набор отключает дедуп, и карта доходит до
аудита. Правок пайплайна не требуется: `run_batched` уже принимает
`done_guids` параметром.

При успешном переаудите `upsert()` ставит `broken = FALSE`
(`src/storage/done_cards_storage.py:117`) — флаг снимается сам, отдельного
UPDATE не нужно.

Источник данных — `card_data` из БД, без обращения к 1С. Скрипт работает
офлайн и чинит падения из-за LLM, сети или парсера. Падение из-за битых
данных в самой карте он не чинит — это осознанная граница.

## Интерфейс

```
python scripts/fix-broken.py ORG [-y] [--dry-run] [--num-batches N]
python scripts/fix-broken.py --all [-y] [--dry-run] [--num-batches N]
```

| Аргумент | Смысл |
|---|---|
| `ORG` | Организация: `Alenka` или `MDS`. Взаимоисключающ с `--all` |
| `--all` | Все организации разом |
| `-y` | Пропустить подтверждение |
| `--dry-run` | Показать, что будет переаудировано, и выйти без записи |
| `--num-batches N` | Параллельных карт за раз (по умолчанию 5) |

Ровно одно из `ORG` / `--all` обязательно; ни одного или оба — ошибка
аргументов.

Excel-экспорта и выгрузки по FTP нет. Это ремонтный скрипт: починенные карты
подхватит обычный периодный отчёт, который и так строится из БД за период.

## Группировка по организациям

`AuditPipeline` принимает **один** `org_id` и **один** `card_filter` на
экземпляр (`src/audit/pipeline.py:56`). Оба влияют на запись: `org_id`
проставляется в каждую строку через `upsert`/`upsert_broken`, а `card_filter`
приходит из `load_card_filter(org)` и у организаций разный.

Поэтому в `--all` буквально один прогон недопустим — он проштамповал бы карты
всех клиник одним `org_id` и прогнал через чужой фильтр, испортив атрибуцию.

Вместо этого: одна команда, одно подтверждение, одна сводка, а внутри
broken-строки группируются по своему `organization_id`, и на каждую группу
создаётся свой экземпляр пайплайна с её `org_id` и её фильтром. Строки с
`organization_id IS NULL` образуют отдельную группу с `org_id=None` и пустым
`CardFilter([])`.

При явном `ORG` группа ровно одна — тот же код, частный случай.

## Новый метод хранилища

В `DoneCardsStorage`, по образцу `get_pending`
(`src/storage/done_cards_storage.py:351`):

```python
async def get_broken(self, organization_id: str | None = None) -> list[dict]:
    """Return card_guid + card_data + organization_id for broken rows."""
```

- `WHERE broken = TRUE AND card_data IS NOT NULL` — без `card_data` чинить
  нечего, такие строки не выбираем.
- `organization_id` фильтруется, только когда он передан; иначе берём все
  организации и группируем на стороне скрипта.
- `organization_id` возвращается в выборке — он нужен для группировки в
  `--all`.

## Сводка и повторные сбои

Карта, упавшая снова, остаётся broken: `upsert_broken` перезапишет строку
свежим стектрейсом. Ничего не теряется.

Итог считается **сверкой множества broken-GUID до и после прогона**, а не по
возврату пайплайна. `run_batched` возвращает только успешные пары — упавшие
карты в нём не видны, поэтому единственный надёжный источник итога это
состояние БД.

Печатается в stdout и в лог:

- починено — было broken, стало не broken и не ignored;
- ушло в ignored — см. ловушку ниже;
- осталось broken — с GUID и первой строкой свежего стектрейса по каждой.

## Ловушка: фильтр применяется и при переаудите

`CardFilter` отрабатывает на переаудите так же, как на обычном прогоне. Если
карта упала, а позже в `filterconfig.json` появилась стратегия, под которую
она подходит, — карта не починится, а уйдёт в `ignored` через
`upsert_ignored` (`src/audit/pipeline.py:105`).

Это корректное поведение: фильтр — источник истины о том, какие карты вообще
подлежат аудиту. Но в сводке такие карты выводятся **отдельной строкой**,
чтобы «пропала из broken» не читалось как «починилась».

Констрейнт миграции 014 — `CHECK (NOT (ignored AND broken))` — при этом не
нарушается: `upsert_ignored` ставит `broken = FALSE` в том же UPDATE
(`src/storage/done_cards_storage.py:185`).

## Подтверждение

По образцу `_confirm_period` из `scripts/audit-one-c-period.py`. До запуска
печатается: режим (организация или `--all`), число broken-карт в разбивке по
организациям и применяемые фильтры. Затем `Proceed? [y/N]`.

`-y` пропускает вопрос, `--dry-run` печатает то же самое и выходит с кодом 0,
ничего не записав. Прогон стоит денег на LLM — страховка окупается.

## Тесты

Против реальной БД, как остальные тесты хранилища:

1. **Починка** — broken-карта проходит переаудит, `broken` снимается,
   результаты заполнены.
2. **Повторный сбой** — карта, падающая снова, остаётся broken со свежим
   стектрейсом; старый стектрейс перезаписан.
3. **`--all` с двумя организациями** — каждая карта сохраняет свой
   `organization_id`, ни одна не получает чужой.
4. **`--dry-run`** — в БД не меняется ничего.
5. **`get_broken`** — не возвращает строки с `card_data IS NULL`; фильтрует по
   организации, когда та передана.

Тесты в engine/medkard гоняются точечно — полный прогон падает без инфры.

# Реестр ГРЛС со статусами регистрационных удостоверений

Дата: 2026-08-17. Ветка спек: `specs-2026-08-17` (от `origin/release`).
Реализация — отдельной веткой от ветки спек.

## 1. Зачем

Сейчас справочник лекарств в БД — таблица `drugs` (миграция 010), заполненная из
`resources/Drugs list.csv` (10 520 строк, ЕСКЛП: торговое наименование, МНН,
форма, дозировка, «исключение отдельных групп пациентов»). У неё нет ни статуса
регистрации, ни номера РУ, ни дат — по ней нельзя сказать, что назначенный
препарат снят с регистрации или его РУ истекло. Единственный читатель —
инструмент `search_medicine` (`src/LLM/tools.py`), который отдаёт treatment-чекеру
факт «это лекарство / это МНН / это БАД».

Цель: заменить `drugs` на полноценную выгрузку **Государственного реестра
лекарственных средств (ГРЛС)** со всеми статусами РУ, хранить её в БД, отдавать
статус в `search_medicine`, и подготовить контракт, по которому реестр
синхронизируется в «Искру» (engine) тем же механизмом, что клинреки.

## 2. Источник данных

Архив выгрузки ГРЛС (`grls<YYYY-MM-DD>-1.zip`, ~19 МБ, пример от 2026-08-17)
содержит 8 xlsx-файлов, по одному на состояние записи реестра. Имена файлов
приходят с битой кодировкой (cp437↔cp866) — на них не полагаемся: **статус
читается из маркерной строки внутри листа**.

Структура каждого листа одинакова (проверено на всех 8):

| строка | содержимое |
|---|---|
| 1–2 | пустые |
| 3 | `Государственный реестр лекарственных средств` (колонка D) |
| 4 | пустая |
| 5 | заголовки колонок (C…Q; колонка H без заголовка — страна ЮЛ) |
| 6 | **маркер статуса** (колонка C, напр. `Действующий`) — и в той же строке дата выгрузки `17.08.2026 05:00:00` (в одной из ячеек справа) |
| 7… | данные |

Значения маркеров и объёмы (архив 2026-08-17):

| Маркер | Строк / уник. РУ | Смысл |
|---|---|---|
| `Действующий` | 19 665 / 19 657 | РУ действует, национальная процедура РФ; 7 445 срочных (есть дата окончания), остальные бессрочные |
| `Выдано по правилам ЕАЭС` | 9 259 / 9 252 | РУ действует, выдано/приведено в соответствие с правилами ЕАЭС. Живой статус, не пересекается с «Действующий» |
| `Действует, на подтверждении государственной регистрации` | 77 / 77 | РУ действует, идёт процедура подтверждения (перерегистрации) |
| `Действует, в иностранных упаковках` | 36 / 14 | Разрешён оборот в зарубежной упаковке; по 2–3 строки на РУ (разные упаковки) |
| `Приостановлено применение` | 33 / 33 | РУ живо, применение приостановлено регулятором |
| `Истёкший` | 5 474 / 5 467 | Срок действия РУ истёк (100 % с датой окончания; 3 636 — истекли в 2025) |
| `Исключённый` | 4 342 / 4 054 | РУ аннулировано / исключено из реестра (4 072 с датой аннулирования) |
| `Изменённый` | 102 193 / 28 238 | **Не статус, а журнал редакций**: строка на каждую версию записи (переоформление РУ, «Изм. №N к …»); 27 643 из 28 238 его РУ есть в файлах выше; масса точных дублей. **Не грузим** (решение 2026-08-17). |

Итого в базовом импорте — **7 статусов, ~39 тыс. строк, 39 070 уникальных РУ**
(с учётом «Изменённого»; без него — чуть меньше).

Факты о данных, влияющие на схему:

- **Номер РУ не уникален** даже внутри статуса: `Р N000077/01` в «Действующий» —
  «Рингера-лактат с магнием» (2012), в «Истёкший» — «Лактасол» (2006); в одном
  файле бывают несколько строк одного РУ (разные упаковки, разные редакции НД).
  Уникальный ключ строки — только полный кортеж; вводим `row_hash`.
- Точные дубли строк встречаются (8 в «Действующем», 8 в «иностранных упаковках»)
  — снимаются `row_hash UNIQUE`.
- «Формы выпуска» — одна строка вида
  `таблетки, покрытые пленочной оболочкой, 500 мг, 15 шт. - блистеры (4 шт.) - пачки картонные (60 шт.) - По рецепту; …`
  через `;`. 17.4 тыс. из 19.7 тыс. «Действующих» содержат слово формы, 14 тыс.
  — дозировку; 357 старых строк содержат только `- Без рецепта;` без формы.
  Формат элемента регулярный (392 605 элементов по всем статусам: 98 % содержат
  ` - `, 68 % — слово «рецепт»): **первый сегмент до запятой = лекарственная
  форма** (1 000 уникальных: таблетки 138 тыс., субстанция-порошок 30 тыс.,
  капсулы 26 тыс., раствор для инфузий 17 тыс.…), **последний сегмент после
  ` - ` = условия отпуска** — не бинарные: «По рецепту» 183 210, «Без рецепта»
  77 063, «для стационаров» 55 928, «Не указано» 47 181, «In-Bulk» 18 951, хвост
  («для специализированных учреждений» 1 855, «для производственных отделов
  аптек» 377…); ~2 % мусора (осколки `- Без рецепта` отдельным элементом).
  Храним `forms TEXT[]` как есть **плюс два производных массива**
  `dosage_forms` / `dispensing` (уникальные первые/последние сегменты, §4.2) —
  для сборщика контекста; в подполя дальше (дозировка, фасовка) не парсим,
  дочерних таблиц не заводим (решение 2026-08-17).
- **Фармацевтические субстанции лежат в реестре наравне с препаратами**: 61-ФЗ
  считает «лекарственными средствами» и препараты, и субстанции (сырьё —
  «субстанция-порошок, ~, 25 кг - мешки - барабаны - Не указано»). В выгрузке —
  2 314 строк с номерами `ФС-…` в «Действующем» и 166 в «Исключённом», плюс
  субстанции под обычными номерами. Назначить субстанцию врач не может →
  флаг `is_substance` (§4.2), поиск по умолчанию их не видит.
- **Один номер РУ может лежать в нескольких статус-файлах** (80 номеров):
  перерегистрация сохраняет номер, а старая запись уходит в «Истёкший»
  (`ЛС-001005` Кеторолак: 2005→2010 истёкшая + действующая с 2010); советские
  номера `64/228/156` — по строке на каждую фармфабрику с разными датами
  аннулирования; `П N012990/01` — три торговых наименования, два исключены,
  одно действует. Т.е. «номер аннулирован» — не свойство номера, а строки.
- **Даты внутри реестра противоречивы**: 87 «Действующих» с `expires_at` в
  прошлом; у 1 111 «Исключённых» `annulled_at` позже `expires_at`, у 452 —
  раньше, у 270 её нет вовсе; у «Истёкших» `annulled_at` пуст всегда, у
  «Действующих»/ЕАЭС — тоже. Следствие: **статус берётся из файла, из дат он
  не выводится**; даты — только для интерпретации относительно даты визита
  (§5.1) и для показа.
- Номера ЕАЭС-формата: `ЛП-№(006395)-(РГ-RU)` — Россия референтное государство
  (13 303, сама регистрировала), `ЛП-№(000003)-(ГП-RU)` — Россия государство
  признания (164; зарегистрировано в другой стране Союза, чаще Беларусь). Оба
  живые, для нас неразличимы; в файле «Выдано по правилам ЕАЭС» при этом лежат
  и старые национальные номера (`ЛП-`, `Р N`, `ЛСР-`), приведённые в
  соответствие с правилами Союза. Формат номера ничего не говорит о статусе.
- Пустое значение в выгрузке — либо `''`, либо `~` (напр. МНН `~` у 1 036 строк
  «Действующего»; «Наркотика» `~` у 138 тыс. строк) → оба → `NULL`.
- Даты — `DD.MM.YYYY` (иногда с временем) → парсим → `DATE`. Наружу (тул, логи,
  доки, дампы) — **только ISO `YYYY-MM-DD`**.
- Колонка «Орфанный» пуста во всей выгрузке — колонку заводим (`BOOLEAN NULL`),
  чтобы не менять схему, когда ГРЛС начнёт её заполнять.

## 3. Схема БД (миграция 027)

`migrations/027_grls_registry.sql`. Все колонки снабжаются `COMMENT ON COLUMN`
(смысл + из какой колонки xlsx взято) — текст комментариев = колонки «Смысл» и
«Источник» таблицы ниже.

### 3.1 `grls_registry` — одна строка = одна строка выгрузки

| Колонка | Тип | Источник (xlsx, строка 5) | Смысл |
|---|---|---|---|
| `id` | `BIGSERIAL PK` | — | суррогатный ключ |
| `status` | `TEXT NOT NULL CHECK (status IN (7 значений))` | маркер в строке 6 | состояние записи реестра (см. таблицу §2); значения хранятся дословно как в выгрузке |
| `reg_number` | `TEXT NOT NULL` | «Номер регистрационного удостоверения» | номер РУ (`ЛП-000001`, `Р N000077/01`, `70/367/30`…) — **не уникален** |
| `registered_at` | `DATE` | «Дата регистрации» | дата выдачи РУ |
| `expires_at` | `DATE` | «Дата окончания действия регистрационного удостоверения» | срок действия РУ; `NULL` = бессрочно |
| `annulled_at` | `DATE` | «Дата аннулирования регистрационного удостоверения» | дата аннулирования (заполнена в основном у «Исключённый») |
| `holder` | `TEXT` | «Юридическое лицо, на имя которого выдано регистрационное удостоверение» | держатель РУ |
| `holder_country` | `TEXT` | безымянная колонка H (сразу после ЮЛ) | страна держателя РУ |
| `trade_name` | `TEXT NOT NULL` | «Торговое наименование лекарственного препарата» | торговое наименование |
| `inn_name` | `TEXT` | «Международное непатентованное или химическое наименование» | МНН / группировочное / химическое; `~` → `NULL` |
| `forms` | `TEXT[] NOT NULL DEFAULT '{}'` | «Формы выпуска», split по `;`, trim, пустые выброшены | формы выпуска: «форма, дозировка, фасовка - упаковка - … - условия отпуска» |
| `forms_raw` | `TEXT` | «Формы выпуска» как есть | исходная строка для отладки парсера |
| `dosage_forms` | `TEXT[] NOT NULL DEFAULT '{}'` | производное от «Формы выпуска» (§4.2) | уникальные лекарственные формы: первый сегмент каждого элемента до запятой («таблетки», «раствор для инфузий») |
| `dispensing` | `TEXT[] NOT NULL DEFAULT '{}'` | производное от «Формы выпуска» (§4.2) | уникальные условия отпуска: последний сегмент после ` - » («По рецепту», «Без рецепта», «для стационаров», «Не указано», «In-Bulk», …) |
| `is_substance` | `BOOLEAN NOT NULL DEFAULT false` | производное от номера РУ и «Формы выпуска» (§4.2) | фармацевтическая субстанция (сырьё), а не препарат; поиск по умолчанию исключает |
| `production_stages` | `TEXT` | «Сведения о стадиях производства» | производители по стадиям («Все стадии, ООО …, адрес, страна») |
| `normative_docs` | `TEXT` | «Нормативная документация» | реквизиты НД/ФС и редакций РУ (`ЛП-000001-280722,2022,…; Изм. №1 к …`) |
| `pharm_group` | `TEXT` | «Фармако-терапевтическая группа» | ФТГ |
| `is_vital` | `BOOLEAN` | «Наличие лекарственного препарата в перечне ЖНВЛП» (`Да`/`Нет`) | входит ли в перечень ЖНВЛП |
| `narcotic_list` | `TEXT` | «Наличие в лекарственном препарате наркотических средств, психотропных веществ и их прекурсоров» | список ПКУ по ПП РФ № 681: `НII` (список II наркотических), `ПII` (список II психотропных), `ПIII` (список III психотропных), `ПК` (прекурсоры); `~`/`Нет` → `NULL` = не содержит |
| `is_orphan` | `BOOLEAN` | «Орфанный» | орфанный препарат; в выгрузке 2026-08 пусто у всех → `NULL` |
| `row_hash` | `TEXT NOT NULL UNIQUE` | вычисляется | sha256 нормализованного кортежа (см. §4.3) — ключ дедупликации и синка |
| `imported_at` | `TIMESTAMPTZ NOT NULL DEFAULT now()` | — | момент загрузки |

Индексы:

- SQL-функция `grls_norm(text) RETURNS text IMMUTABLE` (в той же миграции) —
  зеркало `normalize_query` (§5): `lower`, схлопывание пробелов, удаление
  `®™©` и кавычек, `ё`→`е`, `~`→пусто;
- `grls_registry_trade_name_trgm_idx` — `GIN (grls_norm(trade_name) gin_trgm_ops)`;
- `grls_registry_inn_trgm_idx` — `GIN (grls_norm(inn_name) gin_trgm_ops)` —
  оба функциональные, чтобы нормализованное сравнение шло по индексу (сейчас
  `search_by_inn` делает `LOWER()` мимо индекса);
- `grls_registry_status_idx` — btree `status`;
- `grls_registry_reg_number_idx` — btree `reg_number`;
- `grls_registry_is_substance_idx` — btree `is_substance` (partial `WHERE
  is_substance` не нужен: колонка используется как фильтр `NOT is_substance`
  вместе с trgm-индексом, планировщик справится; при необходимости — на
  реализации по `EXPLAIN`).

## 4. Загрузчик `scripts/import-grls.py`

```
python scripts/import-grls.py <archive.zip | dir-with-xlsx> [--dry-run] [--keep-staging]
```

### 4.1 Чтение

- Архив распаковывается во временный каталог; берутся все `*.xlsx`.
- `openpyxl.load_workbook(read_only=True)`, первый лист, потоково.
- Строка 5 — заголовки: сверяем ожидаемые заголовки по префиксам (`Номер
  регистрационного удостоверения`, `Дата регистрации`, …); несовпадение →
  ошибка с указанием файла (защита от смены формата выгрузки).
- Строка 6 — маркер: `status = cell(C)`; дата выгрузки — первая ячейка строки,
  парсящаяся как `DD.MM.YYYY[ HH:MM:SS]`. Маркер `Изменённый` → файл
  пропускается (лог + `skipped_files`). Неизвестный маркер → ошибка.
- Данные с 7-й строки; строка без `reg_number` или без содержимого в остальных
  колонках пропускается.

### 4.2 Нормализация

| Поле | Правило |
|---|---|
| строки | `strip()`; `''` и `~` → `NULL`; `_x000D_\n` → `\n` (артефакт xlsx-экспорта в `normative_docs`/`production_stages`) |
| даты | `DD.MM.YYYY` (с опциональным временем) → `date`; пусто → `NULL`; нераспарсенное → warning + `NULL` |
| `forms` | `forms_raw.split(';')` → `strip()` каждого → без пустых |
| `dosage_forms` | по каждому элементу `forms`: сегмент до первой `,` → `strip()`; элементы, начинающиеся с `-` (осколки), пропускаются; уникальные, порядок первого появления |
| `dispensing` | по каждому элементу `forms`: `rsplit(' - ', 1)[-1]` → `strip()`; если ` - ` нет — элемент пропускается; уникальные, порядок первого появления. Значения не нормализуем к словарю (хвост длинный) — как есть |
| `is_substance` | `reg_number.startswith('ФС-')` **или** хотя бы одна из `dosage_forms` начинается с `субстанция` (регистронезависимо) |
| `is_vital` | `Да` → `true`, `Нет` → `false`, иное → `NULL` |
| `narcotic_list` | `~`/`Нет`/пусто → `NULL`, иначе как есть |
| `is_orphan` | `Да`/`Нет` → bool, пусто → `NULL` |

### 4.3 `row_hash`

`sha256` от `'\x1f'.join(...)` нормализованных строковых представлений в
фиксированном порядке: `status, reg_number, registered_at(ISO|''),
expires_at, annulled_at, holder, holder_country, trade_name, inn_name,
forms_raw, production_stages, normative_docs, pharm_group, is_vital('1'|'0'|''),
narcotic_list, is_orphan`. `imported_at`, `id` и производные колонки (`forms`, `dosage_forms`,
`dispensing`, `is_substance`) не входят — они детерминированно выводятся из
`forms_raw`/`reg_number`. Алгоритм — контракт синка (§7): engine обязан уметь
пересчитать тот же хеш из дампа.

### 4.4 Запись — атомарный swap

1. `CREATE TABLE grls_registry_staging (LIKE grls_registry INCLUDING ALL)`.
2. `COPY`/batched insert в staging с `ON CONFLICT (row_hash) DO NOTHING`
   (дедуп точных дублей).
3. В одной транзакции: `DROP TABLE grls_registry; ALTER TABLE
   grls_registry_staging RENAME TO grls_registry;` + переименование индексов;
   `INSERT INTO grls_imports (...)`.
4. Итог в лог: `registry_date`, счётчики по статусам, пропущенные файлы.

Так `search_medicine` (и любой читатель) не блокируется на время загрузки
(TRUNCATE держал бы ACCESS EXCLUSIVE lock на минуту). Повторный запуск = полная
замена; загрузчик идемпотентен. `--dry-run` печатает счётчики без записи.

Архив в git **не кладём** (19 МБ, меняется ежемесячно). В `docs/storage.md`
описывается, откуда брать выгрузку (grls.rosminzdrav.ru → выгрузка реестра
xlsx) и команда импорта.

## 5. Storage: `src/storage/grls_storage.py`

`GrlsStorage(BaseStorage)` + dataclass `GrlsRecord` в
`src/storage/models/grls_record.py` (1:1 к таблице).

```python
def normalize_query(text: str) -> str          # чистая функция, см. ниже
async def search_by_trade_name(self, query: str, *, threshold: float = 0.85, limit: int = 6, include_substances: bool = False) -> list[GrlsRecord]
async def search_by_inn(self, query: str, *, limit: int = 20, include_substances: bool = False) -> list[GrlsRecord]
async def latest_import(self) -> GrlsImport | None
```

- **Хранение — как есть, нормализация — в запросе** (решение 2026-08-17).
  `normalize_query`: `lower`, `strip`, схлопывание пробелов, `®`/`™`/`©` →
  пусто, все виды кавычек (`"«»„“”`) → пусто, `ё`→`е`, `~`→пусто. Та же функция
  применяется к колонке в SQL через выражение (`lower(translate(...))`) — чтобы
  сравнение шло симметрично; trgm-индексы строятся по этому же выражению
  (`grls_norm`, §3.1; тест на паритет python↔SQL — стендовый).
- `search_by_trade_name`: `grls_norm(trade_name) % q AND
  similarity(grls_norm(trade_name), q) >= threshold`, порядок — `status_rank ASC, similarity DESC, expires_at DESC
  NULLS FIRST`.
- `search_by_inn`: `grls_norm(inn_name) = q` **или** `grls_norm(inn_name) % q` c порогом
  0.6 (комбинированные МНН вида «амоксициллин+клавулановая кислота» иначе не
  находятся); порядок тот же.
- Оба по умолчанию `AND NOT is_substance`.
- `status_rank` — `CASE` по константе в коде (не в БД):
  живые (`Действующий`, `Выдано по правилам ЕАЭС`, `Действует, на
  подтверждении…`, `Действует, в иностранных упаковках`) = 0;
  `Приостановлено применение` = 1; `Истёкший` = 2; `Исключённый` = 3.
- Порог 0.85 для торгового — как сейчас (`_DRUG_SCORE_THRESHOLD`).

### 5.1 Семантика статуса и дат (`grls_status.py`, чистые функции)

Статус — истина из файла; даты его не переопределяют. Даты нужны для трёх
вещей:

1. **Показ.** «действует до YYYY-MM-DD» / «бессрочно» / «истекло …» /
   «аннулировано …» — всегда ISO. Живой статус с `expires_at` в прошлом
   выводится как есть («Действующий, срок до 2025-12-31») — это дефект
   реестра, не наш вывод; замечанием не считается.
2. **Интерпретация относительно даты визита** — единственное место, где даты
   влияют на смысл, и только в сторону **смягчения**:

   ```python
   class StatusAtVisit(str, Enum):
       ACTIVE = "active"                # живой статус
       ACTIVE_WITH_NOTE = "active_note" # живой, но «на подтверждении» / «в иностранных упаковках» / «приостановлено применение»
       VALID_AT_VISIT = "valid_at_visit"  # сейчас Истёкший/Исключённый, но граница >= даты визита
       EXPIRED = "expired"              # Истёкший, граница < даты визита (или дата визита не передана)
       ANNULLED = "annulled"            # Исключённый, граница < даты визита (или не передана)
       UNKNOWN_END = "unknown_end"      # Истёкший/Исключённый без пригодной границы

   def status_at(record: GrlsRecord, on: date | None) -> StatusAtVisit
   ```

   Граница: для «Истёкший» — `expires_at`; для «Исключённый» — `annulled_at`,
   если пусто — `expires_at`, если и её нет — `UNKNOWN_END` (смягчения нет,
   в тексте «дата неизвестна»). `on=None` (тул без даты визита) → без
   смягчения. Дата визита есть у графа (`visit_context`) — узел `lookup_drugs`
   передаёт её; legacy-тул `search_medicine` — не передаёт.
3. **Версия и провенанс.** `grls_imports.registry_date` — «реестр ГРЛС от
   YYYY-MM-DD» в заголовке справки, логах, sources.

Что из этого следует для судьи (формулируется в промпте, §6): `EXPIRED` /
`ANNULLED` у назначенного препарата — основание для замечания; `VALID_AT_VISIT`
— **не** основание (на момент визита было легально; факт упоминается в справке);
`ACTIVE_WITH_NOTE` — предупреждение в справке, не замечание о легальности
(решение 2026-08-17: приостановление и подобное — предупреждать, не браковать);
`UNKNOWN_END` — как `ANNULLED`/`EXPIRED`, но с оговоркой «дата неизвестна».
Границу «был ли препарат перерегистрирован под тем же номером» по снимку
восстановить нельзя (старая запись затёрта) — это известное ограничение,
описывается в `docs/storage.md`; полная история — только диффом собственных
снимков (`grls_imports`), в скоуп не входит.

## 6. Инструмент `search_medicine` (`src/LLM/tools.py`)

Имя, `args_schema` (`query`) и место подключения (`get_treatment_tools_for`) не
меняются — treatment-чекер продолжает работать до перехода на граф (спека
`2026-08-17-diagnosis-graph-design.md`); после перехода ту же логику вызывает
узел `lookup_drugs` напрямую через `GrlsStorage`, без тула. Форматирование
выносится в чистую функцию `format_medicine_lookup(records, supplements, *,
on: date | None, registry_date: date | None) -> str`, которой пользуются оба
(`on` — дата визита для `status_at`, §5.1; тул передаёт `None`).

Порядок и текст ответа:

1. `search_by_inn(query)` нашёл → «В ГРЛС «{query}» — это МНН. Регистраций: N,
   из них действующих: M. Примеры торговых наименований: A, B, C.» (+ если
   действующих 0 — «внимание: все РУ по этому МНН истекли/аннулированы»).
2. Иначе `search_by_trade_name(query)` → «Найдено в ГРЛС (N):» и на каждую
   запись:
   ```
   --- 1 ---
   Торговое наименование: Амоксиклав®
   МНН: амоксициллин + клавулановая кислота
   Статус РУ: Действующий (РУ ЛП-000123, действует до 2027-03-01)
   Лекарственные формы: таблетки, покрытые плёночной оболочкой; порошок для приготовления суспензии
   Отпуск: По рецепту
   ФТГ: антибиотик-пенициллин полусинтетический + бета-лактамаз ингибитор
   ЖНВЛП: да
   ```
   «Лекарственные формы»/«Отпуск» — из `dosage_forms`/`dispensing` (не сырой
   `forms`; кап 5 значений, `+ ещё K`). Строка статуса — по `status_at`:
   «Истёкший (истекло 2025-12-31)» / «Исключённый (аннулировано 2024-02-14)» /
   «Истёкший (истекло 2025-12-31; **на дату визита 2025-03-10 действовало**)» /
   «Исключённый (дата неизвестна)» / «Действующий, **приостановлено применение**
   (предупреждение, не запрет назначения)» / «Действующий, на подтверждении
   регистрации» / «Действующий, в иностранной упаковке». Субстанции в выдачу не
   попадают. Не более 6 записей.
3. Иначе — БАД-фолбэк как сейчас.
4. Иначе — «Препарат или БАД не найден в реестрах».

Описание тула: «реестр ЕСКЛП» → «ГРЛС»; упомянуть, что ответ содержит статус РУ.
`treatment_checker.txt`: добавить правила из §5.1 — истёкшее/аннулированное
**на дату визита** РУ у назначенного препарата — основание для замечания;
«на дату визита действовало» — нет; приостановление/подтверждение/иностранная
упаковка — предупреждение, не замечание о легальности; «не найден в реестрах»
— повод проверить написание, а не утверждать нелегальность (формулировки — на
реализации; без оверфита под фикстуру).

## 7. Контракт канона для синка в «Искру» (engine)

Механизм — копия синка клинреков (`engine/src/engine/integrations/clinrec/`:
`client.py` читает канон medkard напрямую по `CLINREC_SYNC_DSN` или из
JSONL-дампа; `exporter.py` строит план по хешу; запуск руками
`scripts/clinrec/clinrec_sync.py`, идемпотентен). Реализация в engine — отдельная
ветка/спека; здесь фиксируется то, что medkard гарантирует:

- **Канон** = таблицы `grls_registry` и `grls_imports` с колонками §3 — имена
  и типы стабильны (аналог `guidelines`/`docs`); engine делает
  `_assert_canon_schema` по ним.
- **Ключ синка** = `row_hash` (алгоритм §4.3). План на стороне engine:
  `new = canon_hashes − engine_hashes` → insert, `gone = engine_hashes −
  canon_hashes` → delete; версия — `grls_imports.registry_date` (engine хранит
  её у себя и пишет в лог/сорсы «реестр ГРЛС от 2026-08-17»).
- **Дамп** для стендов без доступа к канону: JSONL(.gz), строка = запись
  `grls_registry` без `id`/`imported_at`, даты — ISO-строки, `forms` — список;
  первая строка — заголовок `{"_meta": {"registry_date": "2026-08-17",
  "archive_name": "...", "row_count": N}}`. Дамп делает
  `scripts/import-grls.py --make-dump FILE` (в этой спеке — да, чтобы формат
  был зафиксирован кодом, а не текстом).
- Набросок engine-стороны (для будущей спеки): `integrations/grls/{client,
  importer, exporter}.py`, `scripts/grls/grls_sync.py --from-db|--from-dump|
  --make-dump|--dry-run`, таблица `drug_registry` той же формы, `GRLS_SYNC_DSN`
  в `.env`, тул `search_drug` для ролей.

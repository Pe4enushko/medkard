# Эвал детерминистичных правил на выгрузках data_snapshots

Замер 2026-09-03 по `~/projects/data_snapshots` — 90 файлов, 76 МБ,
**12 991 карта**: Алёнка 4117, МДС 8874. Формат у выгрузок разный: у Алёнки
`{"appointments": [...]}`, у МДС — голый список.

Скрипты замера — `scripts/checks/eval-deterministic.py`.

---

## 1. Контингент у двух организаций противоположный

| | карт | детей | взрослых | шаблон записи опознан |
|---|---|---|---|---|
| Алёнка | 4117 | **99,9 %** | 0,1 % | 73 % |
| МДС | 8874 | 5,6 % | **94,4 %** | **0 %** |

Два следствия, оба неприятные:

* **`missing_required_fields` не работает у МДС вообще.** Шаблон записи не
  опознаётся ни на одной из 8874 карт — в `resources/required_fields.json`
  описан единственный шаблон `alenka-standard`. Все проверки наличия полей
  осмотра существуют только для Алёнки;
* **168н у Алёнки неприменим по определению.** Порядок адресован взрослым
  18 лет и старше, а у Алёнки таких три карты из 4117.

## 2. Диспансерных приёмов в данных нет

Главный результат замера.

```
диспансерных приёмов найдено:            7 из 12 991  (0,05 %)
из них настоящих диспансерных:           0
```

Все семь — наблюдение беременности, опознанное по коду МКБ `Z34`/`Z34.8`;
услуги там `B01.001.001` (приём акушера-гинеколога) и `A04.30.001.001`
(УЗИ плода). Ни одной услуги раздела `B04.*.001` во всей выгрузке.

При этом **диагнозы из перечней 168н в данных есть**: 719 карт взрослых у МДС
(8,1 %) и 140 у Алёнки. Вот как классифицированы карты МДС с такими диагнозами:

| вид приёма | карт |
|---|---|
| первичный | 494 |
| лабораторные и исследования | 123 |
| `other` | 95 |
| **диспансерный** | **0** |

То есть клиники не кодируют диспансерное наблюдение отдельными услугами —
проводят его под видом обычного приёма. **Правило
`НЕ_ОТРАЖЕНЫ_КОНТРОЛИРУЕМЫЕ_ПОКАЗАТЕЛИ` не срабатывает ни на одной карте.**

### Что было бы без гейта по типу приёма

Гипотетика: взрослый + диагноз из перечней, тип приёма не проверяем.
719 карт, и результат объясняет, почему гейт снимать нельзя:

```
ничего не недостаёт:      8 карт (1,1 %)
медиана недостающих:      9 показателей
максимум:                16
```

Замечание на 99 % карт со списком из девяти пунктов — это не аудит, а шум.

## 3. Срабатывания включённых правил

| правило | Алёнка | МДС |
|---|---|---|
| `УСЛУГА_БЕЗ_КОДА_НОМЕНКЛАТУРЫ` | 321 (7,8 %) | **1359 (15,3 %)** |
| `ПЕРВИЧНЫЙ_ПРИЁМ_БЕЗ_КОДА_МКБ` | 0 | 504 (5,7 %) |
| `ТРАВМА_БЕЗ_КОДА_ВНЕШНЕЙ_ПРИЧИНЫ` | 9 (0,2 %) | 27 (0,3 %) |

**Услуга без кода — 15 % у МДС, и причина одна.** Лабораторные услуги внешней
лаборатории приходят вообще без кода номенклатуры:

```
400  Клинический анализ крови с лейкоцитарной формулой (КДЛ)
328  Аланинаминотрансфераза (АЛТ) (КДЛ)
328  Аспартатаминотрансфераза (АСТ) (КДЛ)
322  СОЭ (венозная кровь) (КДЛ)
311  Креатинин (КДЛ)
```

Это один системный дефект интеграции, а не 1359 разных. Врачу его показывать
бессмысленно — адресат разговор с клиникой. Правило верное, но по адресату
это замечание интеграции, а не записи приёма.

## 4. `OTHER` — треть карт МДС, и почти все безобидны

```
МДС:    3026 карт (34,7 %), из них 2830 (93,5 %) с пустым осмотром
Алёнка:  209 карт (5,1 %),  из них 203 (97,1 %) с заполненным осмотром
```

У МДС `OTHER` — это чистые лабораторные карты: пациент сдал кровь, приёма не
было. Осмотра нет, проверять нечего, вреда от `OTHER` тоже нет.

У Алёнки наоборот — 203 карты с заполненным осмотром падают в `OTHER`:

```
117  B02.031.001   (наименование пустое)
 55  без кода      Оценка внутрикожной пробы с туберкулезным аллергеном
```

Первое — сестринский уход в педиатрии, вида приёма он и не даёт. Второе —
проба Манту без кода услуги и без диагноза `Z11.1`; такие карты должны бы
попадать в `prophylactic_tuberculin`, но опознать их сейчас нечем.

Из 52 рядов **45 встретились** в реальных `ДанныеОсмотра` (10 034 записи

пишет врач. Но применить их сейчас негде — правило, ради которого они
делались, не срабатывает.

## 5a. Вид приёма: код услуги против записи врача

У МДС есть поле `Консультация перв/повтор` — врач сам объявляет вид приёма.
Заполнено на 63,9 % карт с осмотром, 3802 значения: «Первичная» 2563,
«Повторная» 700. У Алёнки такого поля нет.

Сверка с классификатором на 3423 картах с однозначным значением:

| | карт | доля |
|---|---|---|
| совпало | 2433 | 71,1 % |
| **врач «Повторная» — код первичного приёма** | **696** | **20,3 %** |
| у нас `OTHER` | 150 | 4,4 % |
| у нас исследования | 138 | 4,0 % |

Причина: **МДС выставляет все консультации кодом `.001`** независимо от записи.
`B01.023.001` (невролог первичный) — 340 раз, `B01.004.001` — 93, `B01.015.001`
— 75. 804н окончания `.001` и `.002` разводит, клиника этим не пользуется.

Отсюда правило `ВИД_ПРИЁМА_НЕ_СООТВЕТСТВУЕТ_КОДУ_УСЛУГИ` — 697 карт, 7,9 % у
МДС, 0 у Алёнки.

### Поле описывает текущий приём, а не следующую явку

Проверено двумя способами, потому что рядом лежит поле
`Консультация (повт.план итд)` с планом явки («повторная с результатами
обследования через 2 недели»), и спутать их легко:

* у карт с «Повторная» более ранний визит того же пациента встречается в 2,5
  раза чаще — 22,9 % против 9,0 % (снепшоты покрывают сорок разрозненных дней,
  поэтому предыдущий визит чаще всего вне окна);
* содержание записи — идущий приём: «В течение многих лет страдает ГБ.
  Настоящее ухудшение с февраля 2026г».

### Опровергнутый довод

Предполагалось, что неверный тип визита даст ложные замечания об анамнезе:
повторному приёму по 274н он не требуется. Замер это опроверг — у МДС анамнез
на повторных приёмах заполняется **чаще**:

| поле | «Первичная» | «Повторная» |
|---|---|---|
| анамнез | 77,9 % | **89,7 %** |
| объективные данные | 74,3 % | **84,9 %** |
| жалобы | 96,5 % | 98,0 % |

Правило обосновано тем, что услуга закодирована неверно, а не тем, что от
этого страдает проверка записи.

## 5b. Шаблона записи у МДС нет

Полей 180 разных, и устроены они по специальностям, а не единым набором:
«Жалобы невролог», «Мышечный тонус невролог», «Жалобы кардиолог», «План
лечения терапевт». Каждый набор покрывает 14–15 % карт. Подход Алёнки — один
шаблон с сигнатурой из 18 полей — здесь не работает; понадобилось бы около
десяти шаблонов, по одному на специальность.

Проверено отдельно, что доля заполненности не менялась в течение периода
выгрузок: до и после 20.08 доли по полям совпадают («Консультация перв/повтор»
63,9 % против 62,2 %, «Анамнез невролог» 15,1 % против 14,4 %). Выборка после
20.08 маленькая — 471 карта против 5472.

## 6. Выводы

1. **Правило по 168н положено на полку** (решение 2026-09-03). Оно корректно
   и обосновано, но диспансерных приёмов в данных нет. Возвращаться, когда
   клиника начнёт кодировать их услугами `B04.*.001` либо когда появится
   другой признак диспансерного наблюдения в выгрузке.

   **Как проверять появление.** Прогнать
   `scripts/checks/eval-deterministic.py <каталог выгрузок>` и посмотреть
   строку `dispensary` в разбивке видов приёма. Сейчас там 7 карт, и все семь
   — беременность по `Z34`. Как только появятся карты с услугами `B04.*.001`,
   правило можно включать.
2. **`ПЕРВИЧНЫЙ_ПРИЁМ_БЕЗ_КОДА_МКБ` и `ТРАВМА_БЕЗ_КОДА_ВНЕШНЕЙ_ПРИЧИНЫ`
   готовы**: 5,7 % и 0,3 %, не шумят.
3. **`УСЛУГА_БЕЗ_КОДА_НОМЕНКЛАТУРЫ` оставлено включённым.** Решение принято
   2026-09-03: требование стоит в техническом задании на интеграцию и в
   руководствах СЭМД, и правила под то, как клиника выгружает данные, не
   подгоняются. 15 % — один системный дефект интеграции, и снижать эту долю
   должна клиника, а не правило. Предложение переадресовать замечание
   интеграции отклонено.
4. **Нужен шаблон записи МДС.** Без него 8874 карты не проверяются на наличие
   полей вовсе — это самая большая дыра в покрытии, и закрывается она не
   нормативкой, а разбором боевых записей МДС.

# Снимок детерминированного слоя аудита

## Зачем это не e2e

У теста есть ожидаемый ответ, здесь его нет: правильность замечания знает врач,
а не файл с фикстурой. Вопрос другой — **что изменилось между двумя состояниями
кода**. Результат снимка не «прошло/упало», а список различий.

Прогонная часть при этом действительно устроена как e2e с базой вместо фикстур:
`done_cards.card_data` хранит исходный JSON карты, поэтому набор карт
переигрывается офлайн, без 1С.

## Почему только детерминированный слой

Аудит состоит из двух разных по природе частей.

**Решает код** — тип визита по коду ЕГИСЗ, возраст пациента, отбор правил,
сверка кода услуги с её наименованием. Чистые функции: сравниваются точно,
бесплатно и без LLM.

**Решает модель** — сработал ли чекер на выбранном правиле. Два прогона одного
и того же кода на одних и тех же картах дадут разные формулировки, а иногда и
разные вердикты. Пока собственный разброс прогонов не измерен, любой диф
нечитаем: непонятно, изменение это или дрожание.

Снимок покрывает первую часть. Вторая — отдельная работа: сначала прогон
одной и той же ревизии дважды, чтобы узнать уровень шума, потом ручная разметка
замечаний (`valid` / `false positive` / `not applicable` / `wrong source` /
`duplicate`) и precision.

## Использование

```bash
# снимок из фикстуры или файла с картами
python scripts/checks/deterministic-snapshot.py snapshot \
    e2e/fixtures/eval_broken_cards/cases.json -o before.json

# снимок из БД (POSTGRES_* из окружения)
python scripts/checks/deterministic-snapshot.py snapshot --from-db --limit 500 -o after.json

python scripts/checks/deterministic-snapshot.py diff before.json after.json
```

Скрипт снимается и на старых ревизиях: разбор возраста и число параметров
`get_rules` определяются на месте. Иначе снимка «до» не существует — а без него
сравнивать не с чем.

Формат снимка — JSON, ключ = GUID карты:

```json
{"336a6d39-…": {"visit_types": ["REPEAT"], "age": 34, "icd": ["I10"],
                "rules": ["ОТСУТСТВУЕТ_ДИАГНОЗ", "…"], "nmu_contradiction": false}}
```

## Прогон `origin/release` → `dev` (2026-08-23)

Шесть боевых карт из `e2e/fixtures/eval_broken_cards/cases.json`:

| что произошло | карт |
|---|---:|
| `OTHER` → настоящий тип приёма; правил 8 → 23 и 8 → 17 | 2 |
| остались `OTHER` (в карте нет услуг), ушло `ОТСУТСТВУЕТ_ИНФОРМАЦИЯ_О_СОПРОВОЖДАЮЩЕМ` | 4 |

Среднее число правил на карту: **8,0 → 13,0**.

Неожиданного нет: обе перемены — то, что делалось нарочно. Тип визита теперь
берётся из кода ЕГИСЗ, а возрастной фильтр перестал протекать детским правилом
на взрослого с нечитаемым возрастом.

Оговорка: шесть карт — это отбор «худших» представителей, и в четырёх из них
вообще нет услуг. Перед релизом снимок стоит снять на стенде через `--from-db`
на сотнях карт.

## Происхождение снимка

Каждый снимок содержит ключ `_meta`: ревизия репозитория, путь к `src`, откуда
читается возраст, и число аргументов `get_rules`. `diff` печатает обе стороны
первыми строками и отдельно предупреждает, если ревизия совпала — тогда
сравнивать нечего.

Появилось не от аккуратности: снимки release и dev разошлись по возрасту на 65
картах, объяснить это кодом не удалось (релизный разбор на `AGE: 58` возвращает
58, а в снимке стоял `None`), и проверить, на какой ревизии снят «до», было
нечем. Снимок обязан свидетельствовать о себе сам, иначе сравнение двух файлов
доказывает не то, что кажется.

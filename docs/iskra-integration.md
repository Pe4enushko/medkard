# Push-обновления карт для интеграции с «Искрой»

## 1. Назначение

МИС или 1С должна отправлять карту в MedCheck сразу после проведения приёма.
MedCheck передаёт полученную карту в «Искру». Поэтому врач может работать с
данными текущего дня без ожидания пакетной выгрузки.

Внешняя система не вызывает API «Искры».

## 2. Событие 1С

Выполните `POST /visits/push` после успешного проведения документа приёма в
1С.

Повторно выполните `POST /visits/push`, если проведённый приём изменили и
снова провели. Отправляйте карту для каждого приёма отдельно. Не собирайте
карты за день в один push-запрос.

## 3. HTTP-запрос

Команда MedCheck передаёт базовый URL, значение `org` и API-ключ.

```http
POST <MEDCHECK_API_URL>/visits/push?org=<org>
Authorization: Bearer <MEDCHECK_API_KEY>
Content-Type: application/json; charset=utf-8
```

Тело запроса — один объект карты. Не передавайте обёртку
`{"appointments": [...]}`. Формат объекта карты описан в
`clinic-data-requirements.md`.

```json
{
  "Прием": {
    "GUID": "8d96a4da-018a-4d55-a66c-5962643a23dc",
    "NUM": "123456",
    "DATE": "2026-08-03",
    "Врач_код": "00012",
    "Врач": "Иванова Анна Сергеевна"
  },
  "Врач": {"SPECIALIZATION": "Педиатр"},
  "Пациент": {"CODE": "P-000001", "GENDER": "Женский", "AGE": 12},
  "Услуги": [],
  "ДанныеОсмотра": [
    {"Параметр": "Жалобы", "Значение": "Боль в горле два дня"}
  ],
  "Диагнозы": []
}
```

## 4. Успешный ответ

MedCheck возвращает `200`:

```json
{
  "card_guid": "8d96a4da-018a-4d55-a66c-5962643a23dc",
  "status": "pending"
}
```

`card_guid` должен совпадать с `Прием.GUID` отправленной карты. Статус
`pending` означает, что MedCheck принял карту для обработки.

## 5. Повторы и ошибки

Сохраняйте задачу отправки до ответа `200`. При сетевой ошибке или ответе
`5xx` повторяйте запрос с ограниченной экспоненциальной задержкой. Не
создавайте новую карту при повторе. Отправляйте ту же карту с тем же
`Прием.GUID`.

| Код | Действие |
|---|---|
| `200` | Завершить задачу отправки. |
| `401` или `403` | Остановить повторы. Проверить API-ключ и значение `org`. |
| `422` | Исправить формат карты. Не повторять тот же запрос. |
| `5xx` или ошибка сети | Повторить отправку. |

Не записывайте `MEDCHECK_API_KEY` и полное тело медицинской карты в журналы.

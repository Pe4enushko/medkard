# Операторские сводки по боевым картам

Два скрипта, чтобы после выкатки не сочинять запрос каждый раз. Оба читают
`done_cards` напрямую, интервал задаётся одинаково, детальная выгрузка ложится в
`logs/` и по желанию уезжает по scp.

| Скрипт | Отвечает на вопрос |
|---|---|
| `scripts/stats/stats-findings.py` | какие флаги выставлены, сколько замечаний и на скольких картах |
| `scripts/stats/stats-broken.py` | сколько карт упало и на чём именно |

Общее в `scripts/stats/stats_common.py`: разбор интервала, периоды, запись CSV,
отправка. Отдельным модулем потому, что сводки сравнивают между собой, и
интервал обязан считаться в них одинаково.

## Интервал

```bash
--days 7                      # назад от сегодня, по умолчанию
--from 24.09.2026 --to 29.09.2026
--from 2026-09-24             # ISO тоже принимается
```

`--days 1` — это сегодня: границы включительные с обеих сторон. `--to` по
умолчанию сегодня.

`--by audit` (по умолчанию) считает по времени аудита, `--by visit` — по дате
приёма. После выкатки нужен первый: интересно, что выставил новый код, а карту за
1 сентября могли проверить 29-го. Для разговора с клиникой нужен второй.

## Замечания

```bash
python scripts/stats/stats-findings.py                        # 7 дней, все организации
python scripts/stats/stats-findings.py --days 1 --org MDS
python scripts/stats/stats-findings.py --from 24.09.2026 --to 29.09.2026
python scripts/stats/stats-findings.py --days 30 --detailed --bucket week
python scripts/stats/stats-findings.py --days 3 --detailed --send remoteclaude
```

В сводке: карт за интервал, сколько из них с замечаниями, замечаний на карту, и
таблица по флагам со степенью, числом замечаний, числом карт и долей карт.
Степень и код правила берутся из слепка в самой находке, а не подбираются по
каталогу: каталог ревизуется, а слепок неизменен.

`--detailed` пишет `logs/stats-findings-<от>_<до>[-org].csv` с разбивкой по
периодам: период, организация, флаг, степень, `rule_id`, замечаний, карт. Период
задаётся `--bucket day|week|month`.

## Сломанные карты

```bash
python scripts/stats/stats-broken.py --days 1
python scripts/stats/stats-broken.py --from 24.09.2026 --to 29.09.2026 --org MDS
python scripts/stats/stats-broken.py --days 3 --detailed --send remoteclaude
```

Сломанная карта — `broken = TRUE`, текст падения в `stacktrace` (миграция 012).
В сводке: карт и сломанных по периодам с долей, затем причины — по последней
строке стектрейса, то есть по классу исключения с сообщением.

`--detailed` пишет `logs/stats-broken-<от>_<до>[-org].csv`: GUID карты,
организация, дата приёма, время старта, причина и полный стектрейс.

Почему это первое, что смотрят после выкатки: пропавший файл `resources/` или
правило с опечаткой проявляются картами в `broken`, а не неверными замечаниями.
Починить их потом — `scripts/operator/fix-broken.py`.

## Отправка выгрузки

`--send АЛИАС` отправляет файл сразу, без вопросов — годится для cron. Без
`--send` в интерактивном терминале скрипт спросит алиас, и пустой ответ означает
«не надо». В неинтерактивном — просто напечатает готовую команду `scp`.

Алиас берётся из `~/.ssh/config`, ключей в скриптах нет. Каталог на приёмной
стороне — `projects/logs`, он создаётся при отправке.

**Что уезжает.** Обе выгрузки — агрегаты и метаданные: флаги, счётчики, GUID
карт, стектрейсы. Текста приёма и персональных данных в них нет. Стектрейс может
содержать фрагмент значения поля, если исключение прилетело из разбора записи, —
это единственное место, на которое стоит взглянуть перед отправкой наружу.

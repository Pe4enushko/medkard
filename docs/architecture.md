> обращения к остальной документации.

## Что это за система

**medkard** — система автоматического аудита амбулаторных карт (записей о визитах
пациентов к врачу). Она забирает записи визитов из МИС на базе 1С, проверяет их
LLM-моделью по трём измерениям качества и отдаёт результаты в виде Excel-отчётов
и HTTP-API.

Три измерения аудита:

1. **Формальная структура** — присутствуют ли обязательные разделы записи
   (жалобы, анамнез, осмотр…) для данного типа визита и возраста пациента.
   Правила выведены из приказов МЗ (274н, 203н) и лежат в `rules.json`.
2. **Кодирование МКБ-10** — соответствует ли выставленный код диагноза содержимому
   записи; агент может предложить исправленный код.
3. **Клинические рекомендации** — соответствует ли запись (анамнез, обследование,
   лечение) клиническим рекомендациям Минздрава для этого диагноза. Тексты
   клинреков (PDF) заранее проиндексированы в RAG-хранилище.

Важные факты о данных: визиты приходят из 1С **обезличенными**, LLM и эмбеддинг-модели
работают через self-hosted OpenAI-совместимый эндпоинт (vLLM), база — Postgres
с расширением pgvector.

Акторы:
- **1С МИС** (две организации: Alenka и MDS) — источник визитов.
- **cron на проде** — регулярный запуск скриптов аудита по расписанию
  (crontab стенда, в репозитории не хранится); повторные запуски безопасны
  благодаря дедупликации и кешу.
- **Оператор** — ручные запуски скриптов аудита/ингеста, снятие метрик.
- **Интегрирующее приложение** — единственный клиент pull-API, забирает xlsx и
  сырые строки для аналитической реплики.
- **FTP-сервер** — приёмник готовых Excel-отчётов.

## Пайплайн аудита одного прогона

```
 python scripts/audit-one-c-period.py Alenka --days 3   (на проде — по cron)
 │
 ├─▶ 1. filterconfig.json → CardFilter (настраиваемый per-org набор фильтр-стратегий:
 │       Alenka — IcdFilter Z11.1/Z11.8; MDS — KDLFilter + AnalysisFilter)
 ├─▶ 2. Кеш/1С: JSON визитов за период
 ├─▶ 3. get_done_guids(org) ── GUID уже аудированных карт (дедуп)
 │
 ├─▶ 4. CardFilter.filter(визиты, done_guids)
 │       ├── pending          → в аудит
 │       ├── skipped_done     → уже в БД, пропуск
 │       └── ignored          → upsert ignored=TRUE (срезаны стратегией:
 │                              напр. все диагнозы Z11.1/Z11.8, или чисто лабораторные)
 │
 ├─▶ 5. Параллельный аудит pending (asyncio.Semaphore = num_batches):
 │
 │      ┌───────────────── один визит ────────────────────────────────┐
 │      │ a. FormalValidator.validate()          1 LLM-вызов          │
 │      │    тип визита — детерминированно по НМУ-кодам услуг,        │
 │      │    правила из rules.json по типу+возрасту                   │
 │      │                                                             │
 │      │ b. Диагнозов нет? → сохранить и выйти                       │
 │      │                                                             │
 │      │ c. check_icd_codes()                   1 ReAct-агент        │
 │      │    на ВЕСЬ визит: верно ли закодированы диагнозы;           │
 │      │    видит таблицу доступных клинреков, читает их посекционно │
 │      │                                                             │
 │      │ d. для КАЖДОГО диагноза:                                    │
 │      │    ├─ ClinicRecs: МКБ-код → file_id клинрека                │
 │      │    │  (таблица guidelines; точный код → префикс → LLM)      │
 │      │    ├─ 3 ПАРАЛЛЕЛЬНЫХ ReAct-агента с RAG-тулзами:            │
 │      │    │    anamnesis / inspection / treatment                  │
 │      │    │  (treatment дополнительно ищет по реестру лекарств)    │
 │      │    └─ ICD-агент предложил другой код? → повторный аудит     │
 │      │       диагноза с предложенным кодом (вторая строка отчёта)  │
 │      │                                                             │
 │      │ e. upsert в done_cards: card_data + 3 JSONB-результата      │
 │      │    + токены + тайминги + org_id                             │
 │      │    (исключение на любом шаге → broken=TRUE + stacktrace)    │
 │      └─────────────────────────────────────────────────────────────┘
 │
 ├─▶ 6. ExcelFormatter.export_period() — читает done_cards за период,
 │       пишет xlsx (9 колонок: данные визита + 3 колонки проверок)
 └─▶ 7. (опция) FTP-загрузка отчёта в /YYYY/MM/
```

LLM-вызовов на визит: `2 + 3N` (N — число диагнозов), плюс повторы для
предложенных кодов и точечные «ремонтные» вызовы (см. ниже). Все вызовы идут через
единый `LLMClient` с ретраями (до 3 попыток, температура растёт на 0.15 за попытку)
и structured output (`response_format=json_schema`).

## RAG: как клинреки попадают в поиск и как ищутся

Ингест (офлайн, `scripts/knowledge/reingest-pdfs.py`):

```
resources/manifest.csv ──┐        (справочник: ID, название, коды МКБ, возраст…)
pdfs/<ID>.pdf ───────────┤
                         ▼
   PyMuPDF: оглавление → скип титула/сокращений; детект таблиц
                         ▼
   нарезка по номерным секциям («3.1 Лечение…») → чанки ≤2000 симв (overlap 200)
   таблицы → tabula → JSON-чанки по 8 строк
                         ▼
   эмбеддинг contextual text:  "[<секция>]\n<тело чанка>"   ← ключевой приём
                         ▼
   docs(file_id, chunk, metadata, embedding VECTOR(1024), HNSW-индекс)
   guidelines(file_id, name, mkb[], age_category[], …)     ← из манифеста
   ingest_runs(file_id, status, sha256)                    ← resume/идемпотентность
```

Ретривал (в рантайме, из тулзов агентов):

```
запрос агента ("какие обследования обязательны при J06.9?")
   │ embed(query)
   ▼
1) векторный этап: pgvector HNSW cosine, WHERE file_id = <клинрек>
   + секционный фильтр («лечен» → секция-якорь «3 Лечение» → всё поддерево 3.*)
   + исключение «Список литературы»;  кандидатов = top_k × 6
   ▼
2) BM25 (Python, natasha-токенизация) по этим кандидатам
   ▼
3) RRF-слияние двух ранжирований: score = Σ 1/(50 + rank)
   ▼
топ-4 чанка → форматирование с заголовком (название клинрека, МКБ, секция) → агенту
```

История: раньше применялся reverse HyDE (LLM генерировал по 3 гипотетических
вопроса на чанк, эмбеддились они). Он **удалён** — эмбеддится сам чанк с префиксом
секции, колонка эмбеддинга одна.

## Слои кода

```
src/
├── audit/        оркестрация и три измерения аудита
│   ├── pipeline.py          AuditPipeline — вход, конкурентность, персист
│   ├── filters.py           CardFilter + стратегии (Icd/KDL/Analysis)
│   ├── formal_structure/    FormalValidator + rules.json
│   ├── icd_check/           ICD-агент кодирования
│   ├── diagnosis/           DiagnosisValidator (3 агента) + ClinicRecs
│   └── excel_formatter.py   БД → Excel (пайплайн Excel НЕ пишет)
├── LLM/          LLMClient (ретраи/structured output), фабрика ReAct-агентов,
│                 RAG-тулзы, промпты (*.txt), детектор китайских иероглифов
├── RAG/          ingestion (PDF→чанки→эмбеддинги), retrieval (hybrid search)
├── storage/      psycopg3-классы по таблице на класс; models/ — датаклассы
├── parsers/      разбор JSON 1С, Excel-писатель, канонический порядок осмотра
├── integrations/ клиенты 1С (Alenka/MDS), FTP
├── api/          FastAPI pull-API (/visits/check|pull|export), Bearer-ключи
└── reporting/    result_parser (JSONB→модели), ApiFormatter, метрики
```

БД-стека два: **psycopg3** (весь CRUD, `storage/`) и **asyncpg**
(только векторный поиск, `RAG/retrieval/vector_store.py`) — отдельные пулы к одной базе.

## Ключевые таблицы

```
done_cards      результат аудита карты: card_guid (дедуп-ключ), card_data (сырой визит),
                formal_result / diag_result / icd_check_result (JSONB),
                token_count, time_ms, ignored, broken+stacktrace, organization_id,
                updated_at (триггер; курсор инкрементального экспорта)
docs            чанки клинреков + embedding VECTOR(1024), HNSW
guidelines      справочник клинреков: file_id, name, mkb[], age_category[]
ingest_runs     resume-состояние реингеста (status, sha256 PDF)
drugs /         реестры лекарств и БАД для проверки назначений
 dietary_supplements
organizations   мультиарендность; api_keys + api_key_organizations — доступ к API
```

Вьюха `done_cards_metrics` — агрегаты по дням/организациям (число карт, токены,
wall-clock со слиянием параллельных интервалов).

## Выдача результатов

- **Excel**: 9 колонок — данные визита (специализация, дата, карта, осмотр, услуги,
  диагнозы) + три колонки проверок («по приказам МЗ», «по клин.рекомендациям»,
  «кодирование МКБ»). Дозапись идемпотентна по GUID.
- **FTP**: отчёт грузится в `/ГГГГ/ММ/` (обычный FTP, пассивный режим).
- **pull-API** (FastAPI в Docker, порт только на WireGuard-IP):
  - `GET /visits/check?date=&org=` → `{date, count}` — сверка числа карт;
  - `GET /visits/pull?date=&org=` → xlsx-байты (404, если карт нет);
  - `GET /visits/export?since=&limit=&cursor=&org=` → сырые строки done_cards
    (инкрементально по `updated_at`) — питает аналитическую реплику.
  - Аутентификация: `Authorization: Bearer medkard_…` + `?org=`; в БД хранится только
    SHA-256 ключа; ключ скоупится на список организаций (401 — плохой ключ,
    403 — чужая организация, 404 — неизвестная организация).

## Точечные механизмы, о которых стоит знать сразу

- **Дедупликация**: `done_cards.card_guid` UNIQUE; перед прогоном загружаются все
  GUID организации (включая ignored и broken — они тоже не переаудируются).
- **ChineseDetector**: некоторые модели галлюцинируют CJK-иероглифы в русском тексте;
  каждый issue проверяется регексом, «заражённые» чинятся отдельным LLM-вызовом.
- **Возрастные пороги расходятся**: формальная проверка считает ребёнком `< 18`,
  подбор клинреков — `<= 15`. Это текущее состояние кода, не баг конфигурации.
- **Токены и тайминги** пишутся в done_cards на каждую карту; `scripts/checks/metrics.py`
  показывает агрегаты.
- **Миграции**: `migrations/migrate.sh` с леджером `schema_migrations`;
  осторожно — два файла `013_*`, применяются оба в алфавитном порядке.
- **Тесты**: `pytest` (`pythonpath=src`); полный прогон требует Postgres.

## Быстрый старт

```bash
cp .env.example .env            # Postgres, LLM, эмбеддинги, креды 1С
bash migrations/migrate.sh      # схема БД
python scripts/knowledge/seed-guidelines.py           # манифест → guidelines
python scripts/knowledge/reingest-pdfs.py             # PDF → чанки → эмбеддинги
bash scripts/knowledge/seed-reference-lists.sh        # реестры лекарств/БАД
python scripts/operator/audit-file.py --file data.json          # аудит локального JSON
python scripts/audit-one-c-period.py Alenka --days 1   # боевой прогон
docker compose up -d            # pull-API (только API; аудит — вне контейнера)
```

# Эвал вектора в поиске по реестру лекарств

Самодостаточная папка — копируется на машину, где есть выгрузка ГРЛС и доступ
к эндпоинту эмбеддингов. Движок и его БД не нужны.

## Зачем

Спека engine `docs/superpowers/specs/2026-08-20-grls-integration-design.md`
(§4.5, репозиторий **Искры**, ветка `grls-integration`) закладывает в
`drug_registry` колонку `name_embedding`, HNSW-индекс и фазу эмбеддинга в синке.
Всё это оправдано, только если embedding-модель действительно понимает русские
торговые наименования лекарств. Сомнение обоснованное: «Амоксиклав», «Конкор»,
«Мексидол» — искусственные слова, и модель могла не видеть их в осмысленном
контексте.

Эвал отвечает на вопрос цифрами до того, как это будет реализовано.

## Запуск

```bash
pip install openpyxl                 # для --from-zip
# либо: pip install psycopg2-binary  # для --from-db

python grls_name_eval.py --from-zip ~/projects/grls2026-08-17-1.zip
```

Эндпоинт, ключ и модель берутся **из `.env` репозитория** (ищется вверх от
скрипта), теми же переменными, что использует medkard
(`src/RAG/retrieval/embeddings.py`):

| переменная | что задаёт |
|---|---|
| `EMBEDDING_BASE_URL`, иначе `OPENAI_BASE_URL` | эндпоинт |
| `OPENAI_API_KEY` | ключ |
| `EMBEDDING_MODEL` | модель |

Перебиваются флагами `--base-url`, `--api-key`, `--model`. При старте скрипт
печатает, какой `.env` подхватил и с какими эндпоинтом и моделью пойдёт —
свериться до того, как начнётся эмбеддинг.

Полезные флаги: `--limit N` — размер корпуса уникальных названий (по умолчанию
5000; `0` — все ~30 тыс., честнее и дороже), `--per-level N` — запросов на класс.

**Выгрузка открытых данных (`data-*.csv` / `data-*.json`) не годится**: в ней
ноль торговых наименований и МНН (та же спека, §3.3). Только xlsx-архив ГРЛС или
загруженная таблица `grls_registry`.

## Что индексируется

Флаг `--index`:

- **`blob`** (по умолчанию) — `search_blob`: `торговое | МНН | ФТГ | лекформы |
  отпуск | держатель`. Так делает спека §4.5;
- **`name`** — только торговое наименование (узкий эксперимент).

Режим меняет выводы: с blob'ом МНН и ФТГ лежат **внутри** индексируемого текста
и находятся лексикой, поэтому у вектора остаётся меньше работы, чем в режиме
`name`.

## Что меряется

Четыре способа поиска по одному корпусу и одним запросам:

| метод | что делает |
|---|---|
| `trigram` | только лексика, мера pg_trgm-совместимая (Jaccard по триграммам с паддингом) |
| `vector` | только косинус по эмбеддингу |
| `hybrid` | слияние рангов с весом, как в миграции 084: `r_vec + 0.3 * r_trgm` |
| `hybrid_even` | то же слияние **без весов**: `r_vec + r_trgm` |

`hybrid_even` нужен потому, что вес `0.3` подобран под клинреки и на лекарствах
может не подойти. Равные веса показывают, сколько даёт сама идея слияния,
отдельно от удачности коэффициента: если `hybrid_even` заметно лучше `hybrid`,
коэффициент надо подбирать свой, а не переносить из 084.

## Классы запросов

| класс | что подаётся на вход |
|---|---|
| `L0 exact` | точное название; проверка вменяемости, ожидается ~100% |
| `L1 typo` | регистр, ё/е, ®, пробелы |
| `L2 typo1` | одна опечатка |
| `L3 typo3` | три опечатки |
| `L4 phonetic` | русские искажения на слух (о↔а, е↔и, тс↔ц) |
| `L5 inn2trade` | **МНН на входе, торговое в ответе** |
| `L6 ftg exact` | точная ФТГ |
| `L7 ftg typo` | ФТГ с двумя опечатками |
| `L8 ftg partial` | фрагмент ФТГ («противоопухолевое», «средство растительного») |

Запросы порождаются из записей корпуса, поэтому правильный ответ известен
заранее. Отбираются названия от 5 символов после нормализации; выборка —
`random.sample` с фиксированным зерном, прогоны воспроизводимы.

В `L5` отфильтрованы пары, где МНН лексически похож на торговое
(«Церебролизин» ← `церебролизин`, порог `INN_LEXICAL_MAX = 0.30`): они находятся
лексикой тривиально и семантику не проверяют. В `L6`–`L8` не берутся ФТГ короче
12 символов — это обрывки вроде «прочие».

## Множественный ответ и recall

У классов `L6`–`L8` правильных ответов **много**: одну ФТГ делят десятки
препаратов. Поэтому у каждого запроса не один эталон, а множество, и ранг
считается по **первому релевантному**. У `L0`–`L5` множество из одного элемента,
так что метрика читается одинаково везде:

- **recall@k** — доля запросов, где хотя бы один правильный ответ попал в топ-k
  (k = 1, 5, 10);
- **MRR** — среднее от `1/ранг` первого релевантного;
- **|gold|** — средний размер множества правильных ответов.

Корпус не сокращается под запрос: score считается против **всех** записей, потом
сортировка и позиция эталона.

Из-за разного `|gold|` **классы между собой сравнивать нельзя** — чем больше
множество, тем легче задача. Сравнивать надо методы внутри одного класса.

## Как читать результат

Сравнивать методы **внутри класса**:

- **`vector`/`hybrid` не обходят `trigram` ни в одном классе** — модель не
  понимает ни русские названия лекарств, ни ФТГ. Из спеки убрать колонку
  `embedding`, HNSW-индекс и фазу эмбеддинга; поиск строится на `pg_trgm`, как
  в medkard. Это экономит колонку, индекс на 39 тыс. строк, фазу синка и поход
  к эмбеддеру на каждый запрос.
- **Выигрыш только на `L5`/`L6`** (МНН и точная ФТГ) — взвесить трезво: в режиме
  `--index blob` оба поля лежат внутри индексируемого текста и находятся
  лексикой. То есть в проде этот выигрыш заберут триграммы, и вектор может не
  окупиться. Для проверки прогнать оба режима: `--index blob` и `--index name`.
- **Выигрыш на `L2`–`L4` и `L7`** (опечатки в названии и в ФТГ) — вот это
  настоящий довод за вектор: опечатки лексика переживает хуже всего.
- **`L8 ftg partial`** отвечает на отдельный вопрос: находится ли препарат по
  куску названия группы. Если проседает у всех методов — в промпте подагента
  проговорить, что ФТГ надо называть целиком.
- **`hybrid_even` заметно лучше `hybrid`** — вес `0.3` из 084 под лекарства не
  подходит, подбирать свой.

Результат прогона записать в спеку engine (§4.5) с датой и версией модели:
вывод зависит от модели эмбеддингов, и при её смене эвал надо повторить.

# resources/

Данные, которые читает код и правят руками. В самих json-файлах — только данные:
синтаксиса комментариев в JSON нет, а ключ-заглушка вроде `_comment` замусоривает
файл, который и так правят глазами. Объяснения живут здесь.

| Файл | Что задаёт | Кто читает |
|---|---|---|
| `inspection_formats.json` | шаблоны осмотра клиник: порядок полей и их состав | `parsers/inspection_order.py`, `parsers/inspection_fill.py` |
| `required_fields.json` | поля, отсутствие которых — дефект оформления | `audit/formal_structure/required_fields.py` |
| `manifest.csv` | клинреки: файл ↔ коды МКБ, возрастная категория | `RAG/ingestion/data_loader.py`, `audit/diagnosis/clinic_recs.py` |
| `demo_doctors.json` | заплатка демо-врача под показ | `api/demo_doctors.py` |
| `nomenclature-804n.csv` | номенклатура медицинских услуг 804н: код, наименование, статус | `scripts/checks/check-nmu-classifier.py`, `tests/test_nmu_classifier_vs_804n.py` |
| `168n_appendices.csv` | перечни диспансерного наблюдения 168н: код МКБ, периодичность, контролируемые показатели | `audit/deterministic/indicators.py` |
| `168n_indicators.json` | синонимические ряды контролируемых показателей | `audit/deterministic/indicators.py` |

## inspection_formats.json — шаблоны осмотра

Одна запись осмотра (`ДанныеОсмотра`) приходит из 1С списком пар
`{"Параметр": имя, "Значение": текст}` в произвольном порядке. Шаблон задаёт две вещи:

1. **порядок** — в каком виде поля показываются врачу в отчёте;
2. **состав** — какие поля в записи вообще должны быть. Поля, которого нет,
   отчёт дорисовывает со значением «не заполнено».

Дорисовка нужна потому, что **1С не присылает незаполненное поле вовсе** — ни пустым
значением, ни ключом. По 334 боевым картам Алёнки «поле пришло» и «поле пришло
непустым» совпадают до единицы. Без дорисовки врач не отличает «поле не заполнено»
от «такого поля в шаблоне нет».

Дорисовка живёт только в отчёте: на вход аудита запись уходит такой, какой пришла.

### Структура

```
{ "<Клиника>": { "<шаблон>": { order, never_drawn, signature, min_signature_match } } }
```

- **`order`** — слоты в порядке показа. Элемент списка это:
  - строка — одно или несколько полей через запятую (`"Температура, ЧСС, ЧД"`);
  - список строк — **один** слот, пришедший под разными именами
    (`["На приеме пациент с", "родственник лвн"]`). Слот считается заполненным по
    любому имени, а дорисовывается под первым.

  Ловушка: запятая делит строку на поля, поэтому имя с запятой внутри задаётся
  списком из одного элемента — `["При температуре 37,5  С прием"]`, иначе поле
  разъедется на два слота и дорисуется в каждой карте.

- **`never_drawn`** — слоты, которые упорядочиваются, но пустыми не рисуются: они
  живут в карте вне записи осмотра либо приходят по обстоятельствам приёма.
- **`signature`** + **`min_signature_match`** — по каким полям запись опознаётся как
  заполненная этим шаблоном и сколько их должно совпасть.

Имена полей сверяются нестрого (`labels_match`): регистр, `ё`, лишние пробелы и
двоеточия не важны, допускается расхождение в два символа. Имена короче четырёх
символов сверяются точно — иначе «Фсс» садится на «ЧСС», а «ФР» на «ЧД».

Шаблоны проверяются **в порядке файла**, это и есть порядок приоритета. Запись, не
совпавшую ни с одним шаблоном, отчёт не трогает: шаблона у неё нет, дорисовывать нечем.

Клиника при опознании не спрашивается намеренно: одна клиника присылает несколько
шаблонов, и код услуги их не разделяет — базовый педиатрический приходит и первичным
приёмом, и повторным, и профилактическим.

### Один порядок на все шаблоны клиники

Во всех шаблонах поля идут одной и той же чередой: сопровождающий и
нетрудоспособность → жалобы → анамнезы → витальные → общий статус → осмотр сверху
вниз → стул и мочеиспускание → обследование и лечение → рекомендации. Шаблоны
различаются составом полей, а не их порядком: врач читает отчёт по всем приёмам
подряд и не должен каждый раз искать глазами, где здесь жалобы.

Правило проверяется тестом `test_all_alenka_templates_share_one_order`.

### Шаблоны Алёнки

Наборы, пороги и вторые имена считаны по 334 боевым картам за 20–24.08.2026 —
`~/projects/report-2026-08-27-alenka-inspection-fields.md`.

| Шаблон | Карт | Дорисовок на карту |
|---|---|---|
| `standard` | 261 | 7.2 |
| `vaccination` | 34 | 0.06 |
| `nephrologist` | 5 | 0 |
| `gastroenterologist` | 3 | 0.33 |
| нет шаблона | 31 | не трогаем |

**`standard`** — базовый педиатрический осмотр. Порог опознания ни на что не влияет:
карта приносит либо все 16 полей подписи, либо не больше семи, между 8 и 15 нет ни
одной.

«Диагноз» в `never_drawn`: в записи осмотра он не пришёл ни разу за 334 карты, и это
норма — диагноз едет отдельным блоком карты и стоит в отчёте своей колонкой
«Диагнозы» (есть во всех 261 карте). Строка «Диагноз: не заполнено» говорила бы
врачу, что он диагноза не поставил.

«Пациент нуждается в уходе» дорисовывается в каждой карте: этого поля в выгрузке нет
вовсе, и второго имени у него не нашлось (искали — во всей выгрузке 87 имён полей, ни
одного со словом «уход»; весь блок нетрудоспособности разобран по назначению).
Открытый вопрос к автору шаблона: это непередаваемое поле формы или второе имя
«В выдаче листка нетрудоспособности».

**`vaccination`** — запись о вакцинации, свой шаблон, а не урезанный базовый: из 37
слотов базового он закрывает 13, даже если считать все вторые имена. В наборе только
ядро — поля, пришедшие во всех 34 картах (у «Прививочного анамнеза» и «Предоставленных
документов» 33 из 34). Остальное (вакцина, дата следующей, памятки про температуру и
покраснение, рекомендации) приходит в 20–70% карт: стоит в порядке, но пустым не
рисуется.

Подпись — прививочные поля, которых нет в базовом шаблоне. Базовый проверяется первым:
у 17 карт из 261 прививочные поля приписаны **поверх** полного осмотра.

**`nephrologist`** — 5 карт. Весь осмотр уложен в одно поле «Объективный статус
нефролог» вместо двенадцати строк по системам, из 37 слотов базового закрыто 4.
В наборе только поля, пришедшие во всех пяти; «an_vitae» и «Наследственный анамнез»
(4 из 5) стоят в порядке, но не рисуются.

**`gastroenterologist`** — 3 карты. Поля названы по-аллергологически («Status praesens
аллерголог») — похоже, форму сделали копией аллергологической. Из 37 слотов базового
закрыто 17: половина имён общая, но добавлены органы (Печень, Селезенка, Язык, Живот)
и результаты обследований отдельными полями. В наборе клиническое ядро; УЗИ, ФГДС,
копрограмма и биохимия стоят в порядке, но не рисуются — их приносит пациент, а не
заполняет врач.

**Выборки нефролога и гастроэнтеролога крошечные** (5 и 3 карты). Наборы нужно
пересчитать, когда наберётся хотя бы три десятка карт каждого.

**Без шаблона остаются** туберкулинодиагностика (16 карт, вся запись — одно поле
«Комментарий к вакцинации») и карты из одних «Заметок» или с пустым осмотром (15).
Формы там нет, дорисовывать нечего.

### Вторые имена полей

Одно и то же поле приходит в разных шаблонах под разными именами:

| Слот | Как ещё приходит |
|---|---|
| На приеме пациент с | родственник лвн *(внутреннее имя 1С)* |
| Жалобы на момент осмотра | на момент обращения, прививочный, нефролог |
| Анамнез заболевания | An. morbi |
| Кожные покровы | Кожные прививочные |
| Видимые слизистые | Видимые слизистые оболочки |
| Периферические лимфоузлы | Лимфатические узлы, л/узлы |
| Дыхательная система | Аускультативно дыхание |
| Органы брюшной полости | Живот |
| Рекомендации и назначения | Рекомендации, Рекомендации по лечению |
| Рекомендовано посещение специалистов | Направление к другому специалисту (списком) |

На боевых картах базового шаблона вторые имена закрыли один ложный пропуск
(«л/узлы»), но защищают от главного: дорисовать пустым поле, которое врач заполнил
под другим именем.

Поле **«АНАМНЕЗ»** (18 карт) вторым именем не заведено намеренно: его значения
«отягощен» / «не отягощен» — про наследственность, а не про течение болезни.

### Как добавить шаблон

1. Снять частоты полей по выгрузкам этой группы карт: какое поле в скольких картах.
2. В `order` — все поля группы, чередой из раздела «Один порядок» выше.
3. В набор (то, что не попало в `never_drawn`) — только поля, пришедшие практически
   во всех картах группы. Поле, которое врач заполняет по обстоятельствам, в наборе
   быть не должно: каждая такая строка станет ложным замечанием.
4. `signature` — поля, которых нет у соседних шаблонов клиники, и порог с запасом.
5. Поставить шаблон в файле после более общего: приоритет задаётся порядком.
6. Проверить на боевой выгрузке, сколько дорисовок он даёт на карту.

## required_fields.json — обязательные поля

Отдельный от шаблонов файл и другая задача: шаблон отвечает на вопрос «как запись
должна выглядеть», а этот — «отсутствие какого поля считать дефектом оформления».
Пояснения пока лежат внутри самого файла, в ключах `_comment`; при следующей правке
их стоит перенести сюда.

## nomenclature-804n.csv — номенклатура медицинских услуг

10 441 код приказа 804н: `code`, `name`, `status`. Выгрузка текстового слоя
`804_N_MZ.pdf` (экспорт ГАРАНТ от 06.09.2023, редакция с изм. 16.04.2019,
05.03.2020, 24.09.2020) — это единственный PDF корпуса нормативки, у которого
текстовый слой есть, OCR не нужен. Статусы: 10 435 «действует», 5 «утратила
силу», у `A08.30.022` наименования нет.

**Зачем в репозитории.** Код услуги — главный признак вида приёма, и половина
правил в `audit/formal_structure` отбирается по нему. Проверить классификатор
можно только против всей номенклатуры: ошибки в нём выглядят правдоподобно и
на примерах не видны. Пока выгрузка лежала вне репозитория, сверка требовала
PDF приказа и запускалась руками — теперь её гоняет
`tests/test_nmu_classifier_vs_804n.py`.

**Чего файл не даёт.** Соответствия «код → вид приёма» в приказе нет: п. 2
описывает последние знаки кода как «вид, подвид услуги», без расшифровки.
Нормативны только раздел (п. 5.1) и середина кода — специальность (п. 5.2).
Правило «`.001` первичный, `.002` повторный» — наблюдённая закономерность с
28 нарушителями, и эта выгрузка нужна ровно для того, чтобы её сторожить.

**Когда обновлять.** При новой редакции 804н. Пересобирается флагом
`--pdf` у скрипта сверки. Сама выгрузка заморожена: если Минздрав переставит
окончания кодов, тест об этом не узнает и останется зелёным.

## 168n_appendices.csv и 168n_indicators.json — контролируемые показатели

Приказ 168н — **единственный найденный источник требований, привязанных к
диагнозу**, а не к виду приёма. Всё остальное, что собрано по нормативке,
опирается на вид услуги или тип визита; здесь ключ — код МКБ, то есть ровно то,
что приходит в `Диагнозы[].КодМКБ`.

### 168n_appendices.csv

102 строки трёх приложений: приложение 1 (наблюдение ведёт терапевт) — 34,
приложение 2 (кардиолог) — 13, приложение 3 (состояния, предшествующие
злокачественным новообразованиям) — 55. Колонки идут как в приказе, включая
«кто ведёт / условие».

Выгружено из экспорта КонсультантПлюс редакции от 28.02.2024 (с поправкой 91н),
у которого есть текстовый слой; наш скан pravo.gov.ru — первоначальная редакция
и весь свёрстан боком. Нумерация сплошная, 102 из 102 строк сверены с
официальным сканом по совпадению слов наименования.

**Известный дефект выгрузки.** Две ячейки приложения 2, разорванные между
страницами PDF, сшиты неверно: у строки № 1 (I05-I09, I34-I37) потерян кусок
«нормализованное отношение (не реже 2 раз в год)», у строки № 3
(I20-I25, Z95.1, Z95.5) оборван хвост «пациентам после». Затронуты два
показателя из 302 вхождений — МНО и КТ-ангиография после коррекции аорты.

**Условия применимости.** Колонка «кто ведёт» в 55 строках из 102 — это не
условие, а указание на дополнительного специалиста («приём врача-онколога по
медицинским показаниям»). Настоящих условий, которые по нашим данным не
проверяются, пять: артериальная гипертензия 2-3 степени, ХСН 1-2а стадии,
стеноз внутренней сонной артерии от 40%, гиперхолестеринемия без тяжёлой
дислипидемии, и перечень аритмий. Все пять ограничивают, кому наблюдение
показано, — а не что писать в записи, поэтому на правило по составу записи
не влияют.

### 168n_indicators.json

Синонимические ряды: 52 группы, 119 регулярок. Нужны потому, что **приказ пишет
один и тот же показатель двумя способами** — «АД, ЧСС» и «артериальное
давление, частота сердечных сокращений», «ХС-ЛПНП» и
«холестерин-липопротеины низкой плотности», «Вес (ИМТ)» и «Вес (индекс массы
тела)». Врач в записи волен написать третьим — ряды покрывают и это.

Покрытие: 180 вхождений из 182 измеримых. Оставшиеся два — те самые обрывки
ячеек из дефекта выше.

**Чего в рядах нет намеренно.** Из 156 формулировок приказа 84 — не показатели,
а заключения врача: «отсутствие данных о ЗНО по результатам биопсии»,
«отсутствие признаков прогрессирования». Проверить их сравнением нельзя, и
почти весь третий перечень состоит из них. Правила по третьему приложению
детерминистичными быть не могут.

**Когда обновлять.** При новой редакции 168н. Приказ действует до 01.09.2028.
